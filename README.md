# PixelBean · 拼豆图纸生成器

把**任意一张图片**变成**拼豆图纸**：一个格子 = 一颗豆，格子上标注该用哪个牌子、哪个色号的豆子，再统计每种色号各需要几颗（购物清单）。

全程在你自己的浏览器里运行，图片不会上传到任何服务器，可以离线使用。

> 项目名 PixelBean = 像素（Pixel）+ 拼豆（Bean）。

---

## 这是什么？写给第一次接触拼豆的你

拼豆（也叫哈玛珠、熨珠）是一种手工：用一颗颗小圆柱塑料豆在底板上摆出图案，再熨烫固定。常见做法是先照着一份「像素图纸」，一个格子一颗豆地摆。

手工算这个图纸很麻烦——图片缩小成格子后，每个格子的颜色要挑一个最接近的品牌色号，还要对得起买豆的成本。**PixelBean 就是替你干这件事的**：

```
你的图片  →  自动切成格子  →  每格匹配到品牌色号  →  生成标注色号的图纸  →  统计每种色号要几颗
```

## 它能做什么

- **选择图片**：上传电脑/手机里的 PNG、JPG、WebP、BMP、GIF（取首帧）图片，或直接用内置的两张示例图（照片、像素角色）。
- **一键目标模式**：照片、卡通插画、线稿、像素表情包——选一个预设就能得到合适的配置；手动改过参数后自动进入「自定义」模式。
- **图纸尺寸**：按长边格数（32 / 58 / 100 / 200 格），或按方形底板（32×32 / 52×52 / 78×78 / 104×104 / 120×120，即说明书上常见底板规格）。
- **品牌色号匹配**：内置三个品牌色板——MARD 291 色、Perler Standard 103 色、Hama Midi 92 色。每格标注色号和品牌。
- **照片优化开关**（新手可全部默认）：
  - 智能限色：把颜色压到指定数量（24 ~ 313 档位，或自定义上限 400），减少买豆成本；
  - 噪点清理：去掉孤立杂点；
  - 暗部简化、自动描边、细节保护：让成品更贴近原图、更好拼。
- **用量统计与导出**：每种色号需要几颗豆，一目了然；可导出 PNG 图纸、CSV 清单，或直接打印。

## 3 分钟上手

1. 打开页面（本机运行或访问部署好的网址）。
2. 上传一张图片，或点内置示例。
3. 选择目标模式（第一次用选「照片」或「卡通插画」就行）和底板尺寸。
4. 在图纸上点任意格子，可以查看这个格子用哪颗豆。
5. 点「统计」看色号清单，然后用「导出 PNG / CSV / 打印图纸」带走成品。

## 在本机运行

只需要装了 [Node.js](https://nodejs.org/)（**≥ 18**，推荐 20 LTS 或 22 LTS，自带 npm）。

```bash
git clone <仓库地址>      # 或用"下载 ZIP"方式获取代码
cd pixelbean
npm install               # 安装依赖（首次约需几分钟）
npm run dev               # 启动开发服务器
```

然后打开终端提示的地址（一般是 <http://localhost:5173>）即可使用。

常用命令：

| 命令 | 作用 |
|---|---|
| `npm run dev` | 启动开发服务器，改代码即时生效 |
| `npm run build` | 打包出可部署的静态文件（在 `dist/` 目录） |
| `npm run preview` | 本地预览打包后的成品 |
| `npm test` | 跑单元测试 |
| `npm run validate:palette` | 校验内置色板数据格式 |

> `npm run dev` 第一次运行会先自动从 `data/palettes/` 生成色板模块，属正常现象。

### 想发布到网上？

`dist/` 是纯静态文件，随便找个地方托管即可（GitHub Pages / Vercel / 自己的 Nginx 等），具体步骤见 [docs/08-部署指南.md](docs/08-部署指南.md)。

## 它是怎么工作的（给好奇的人）

- **配色不是简单"谁近算谁"**：用 CIEDE2000 色差公式匹配，结果更接近人眼感受；颜色换算在后台线程（Web Worker）里算，不卡界面。
- **图纸用 Canvas 绘制**：上万格子的图纸也能流畅缩放、平移、点击查看。
- **算法可以复现**：图像处理是纯函数，配了确定性单元测试和黄金样例，同一张图每次结果一样。

## 项目结构（想改代码时看这里）

```
src/
  app/        界面：上传、参数面板、图纸预览、统计、导出
  core/       核心算法：降采样、配色、后处理、渲染
  export/     导出：PNG / CSV / 打印
  worker/     后台计算线程
data/
  palettes/   内置品牌色板 JSON
  provenance/ 色板数据的来源与许可证记录
docs/         产品规格、架构设计、算法说明、部署指南、测试报告等全部资料
```

## 给维护者：本仓库的开发约定

本项目按「设计 → 实现 → 审查」的流水线开发，历史记录在 `docs/` 中（阶段 2 产物必须跑得起来并按验收清单自测；阶段 3 必须真实启动项目复现问题，禁止只看代码）。约定如下：

1. **文档是唯一事实来源**：`docs/` 与 `data/` 先行定稿，实现代码不得与其冲突；若需变更，先改文档再改代码。
2. **许可证红线**：禁止从来源不明或 AGPL/GPL 授权的仓库复制代码与色表数据；仅可参考思路或照搬已标注「可复用」的内容（详见 `docs/00`、`docs/04`）。
3. **原创优先**：项目代码均为原创；内置色表数据按 `docs/04` 指定的来源引入，并保留来源与许可证记录于 [data/provenance/README.md](data/provenance/README.md)。
