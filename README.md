# PixelBean · 拼豆图纸生成器

把**任意一张图片**变成**拼豆图纸**：一个格子 = 一颗豆，格子上标注该用哪个牌子、哪个色号，再统计每种色号各需要几颗（= 购物清单）。

**默认全程在你自己的浏览器里运行**：上传、转换、配色、导出都在本机完成，**默认不把图片发到任何服务器**；
应用本体是纯静态文件，可离线使用。
> ⚠️ **唯一例外**：主动打开「**AI 抠图（增强）**」时，图片会被发送到**本站服务器**算一次抠图
> （服务端不保存图片；详见下方「诚实边界」与 [docs/47](docs/47-v1.2-服务端AI抠图-架构变更与Runbook.md)）。

> 项目名 PixelBean = 像素（Pixel）+ 拼豆（Bean）。

---

## 这是什么？写给第一次接触拼豆的你

拼豆（也叫哈玛珠、熨珠）是一种手工：用一颗颗小圆柱塑料豆在底板上摆出图案，再熨烫固定。常见做法是先照着一份「像素图纸」，一个格子一颗豆地摆。

手工算这个图纸很麻烦——图片缩小成格子后，每个格子要挑一个最接近的品牌色号，还要对得起买豆的成本。**PixelBean 就是替你干这件事的**：

```
你的图片  →  切成格子  →  每格匹配品牌色号  →  生成标注色号的图纸  →  统计每种色号要几颗
```

## 它能做什么

- **选择图片**：上传电脑/手机里的 PNG、JPG、WebP、BMP、GIF（取首帧），或直接用内置示例图。
- **一键目标模式**：照片 / 卡通插画 / 线稿 / 像素表情包——选一个预设即可；手动改过参数后自动进入「自定义」。
- **图纸尺寸**：按长边格数（32 / 58 / 100 / 200 格），或按方形底板（32×32 / 52×52 / 78×78 / 104×104 / 120×120，即说明书上常见的底板规格）。
- **品牌色号匹配**：内置三个色板——MARD 291 色、Perler Standard 103 色、Hama Midi 92 色；每格标注色号与品牌。
- **照片优化开关**（新手可全默认）：智能限色（24~313 档或自定义上限）、噪点清理、暗部简化、自动描边、细节保护。
- **去背景**（两个开关，**默认都关**，按需使用）：
  - **一键去背景**：靠颜色/边缘判断，适合纯色或干净背景的图，**完全在本机算**；
  - **AI 抠图（增强）**：靠神经网络处理「白底 + 近白主体 + 软阴影」这类难图。**图片会上传到本站服务器计算**（约 2~4 秒，服务端不保存），**用户不需要下载任何模型**。
- **用量统计与导出**：每种色号几颗一目了然；可导出 PNG 图纸、CSV 清单，或直接打印。

## 3 分钟上手

1. 打开页面（本机运行，或访问你部署好的网址）。
2. 上传一张图片，或点内置示例。
3. 选目标模式（第一次用选「照片」或「卡通插画」）和底板尺寸。
4. 点图纸上任意格子，可以看这个格子该用哪颗豆。
5. 点「用量导出」看色号清单，再用「导出 PNG / CSV / 打印图纸」带走成品。

## 在本机运行

只需装 [Node.js](https://nodejs.org/)（**≥ 18**，推荐 20 LTS 或 22 LTS，自带 npm）。

```bash
git clone https://github.com/zbbkl/pixelbean.git
cd pixelbean
npm install          # 安装依赖（首次约需几分钟）
npm run dev          # 启动开发服务器
```

然后打开终端提示的地址（一般是 <http://localhost:5173>）即可使用。

| 命令 | 作用 |
|---|---|
| `npm run dev` | 启动开发服务器，改代码即时生效 |
| `npm run build` | 打包出可部署的静态文件（输出到 `dist/`） |
| `npm run preview` | 本地预览打包后的成品 |
| `npm test` | 跑单元测试（vitest；当前 224 例通过；接口类用例需设 `AI_SERVICE_URL` 才跑） |
| `npm run validate:palette` | 校验内置色板数据格式是否符合契约 |

> `npm run dev` 与 `npm run build` 会先自动从 `data/palettes/` 生成色板模块，属正常现象。
> 色板数据的采集/归一化/交叉核对脚本在 `data/scripts/`（`fetch:sources`、`normalize:palette`、`crosscheck:palette`、`generate:palettes`），日常开发用不到。

### 想发布到网上？

`dist/` 是纯静态文件，托管到任意静态服务即可（GitHub Pages / Vercel / Nginx…），步骤见 [docs/08-部署指南.md](docs/08-部署指南.md)。

**如果要用「AI 抠图」，需要额外部署一个服务端小服务**（纯静态托管无法提供 AI 抠图）：

| 项 | 值 |
|---|---|
| 组成 | Node 20 + `onnxruntime-web`（WASM）+ 模型权重，仅监听 `127.0.0.1:8790`，由 nginx 反代到 `/pixelbean/api/` |
| 代码 | [`server/ai-mask/`](server/ai-mask/README.md)（含 systemd 单元与 nginx 片段） |
| 没有它会怎样 | AI 开关会失败并**自动落回**确定性抠图，界面给出提示，其它功能不受影响 |
| 详细步骤 | [docs/47](docs/47-v1.2-服务端AI抠图-架构变更与Runbook.md) |

## 它是怎么工作的（给好奇的人）

- **配色不是简单「谁近算谁」**：用 CIEDE2000 色差公式匹配，更贴近人眼感受；换算跑在后台线程（Web Worker），不卡界面。
- **图纸用 Canvas 绘制**：上万格也能流畅缩放、平移、点击查看。
- **算法可以复现**：图像处理是纯函数，配了确定性单测与黄金样例，同一张图每次结果一致。
- **AI 抠图是「可选增强」**：默认关闭、默认不存在任何网络依赖。开启后，浏览器把图片**缩放到模型输入尺寸后的像素**发给本站服务端（`/pixelbean/api/mask`），服务端做归一化 + 推理 + 阈值，**返回一张掩码**（不是图片），前端再走与「一键去背景」**完全相同**的管线与可靠度门。因此服务端不需要任何图像编解码库，也不需要保存图片。见 [docs/47](docs/47-v1.2-服务端AI抠图-架构变更与Runbook.md)。

## 诚实边界（我们不想让你踩坑）

| 情况 | 实际行为 |
|---|---|
| 一键去背景（确定性）遇到「白底 + 近白主体 + 软阴影」 | 该图**颜色判据天然失效**（背景自身的颜色跨度比主体与背景的差异还大）。实现会判定「不可信」并**完整回退**：出图与不开开关完全一样，并在开关下方提示「这张图没找到可分离的背景…」。这是刻意设计，宁可不动，也不吃掉主体。详见 [docs/44](docs/44-v1.2-去背景A+B修订自测报告.md) §12 |
| AI 抠图（增强）**会上传图片** | 这是它唯一的例外：图片会发送到本站服务器算一次抠图（**服务端不保存**，只把结果掩码发回）。若你不希望图片离开设备，**不要打开这个开关**——「一键去背景」与其它全部功能都在本机完成。 |
| AI 抠图耗时 | 服务端推理，通常 2~6 秒（取决于服务器负载与你的网速）；**不需要下载模型** |
| AI 抠图失败/离线/服务器不可用 | 自动**落回**确定性抠图（开关仍生效，只是换算法），界面给出提示，不会吞掉主体、也不会出空图纸 |
| AI 抠图与接触阴影 | 当前模型的输出**不包含**地面接触阴影（这通常更符合图纸观感，因为阴影在拼豆里会变成一圈灰边） |
| 两个去背景开关 | **互斥**，开一个会自动关掉另一个；默认都是关 |
| Perler/Hama 色板的 hex | 为社区整理的工程近似色，与实物存在色差；**图纸以色号为准** |

## 项目结构（想改代码时看这里）

```
src/
  app/        界面：上传、参数面板、图纸预览、统计、导出
  core/       核心算法：降采样、配色、后处理（含取色/抠图）、渲染
  export/     导出：PNG / CSV / 打印
  worker/     后台计算线程（含可选 AI 抠图的服务端调用客户端）
server/
  ai-mask/    可选：服务端 AI 抠图（Node + onnxruntime-web WASM + systemd/nginx 片段）
data/
  palettes/   内置品牌色板 JSON
  scripts/    色板数据的采集与校验脚本
  provenance/ 色板与 AI 模型数据的来源、许可证、SHA-256 记录
tests/
  unit/       单元测试（纯算法、确定性）
  acceptance/ 验收门禁（含权威真实样例、AI 抠图路径）
docs/         产品规格、架构、算法、部署、历次自测与审查报告
```

## 给维护者：本仓库的开发约定

按「设计 → 实现 → 审查」流水线开发，全过程留档在 `docs/`。约定：

1. **文档是唯一事实来源**：`docs/` 与 `data/` 先行定稿，代码不得与其冲突；要变更就先改文档。
2. **许可证红线**：禁止从来源不明或 AGPL/GPL 授权的仓库复制代码、色表与模型权重；只借鉴思路，或使用已标注可商用（MIT / Apache-2.0）并留档的构件（详见 [docs/00](docs/00-调研结论与借鉴清单.md)、[docs/04](docs/04-色号表数据设计.md)）。
3. **原创优先**：项目代码均为原创；外部数据与模型按 `docs/04`、`docs/45` 指定的来源引入，来源/许可证/SHA-256 一律记入 [data/provenance/README.md](data/provenance/README.md)。
4. **不许静默失败**：功能不可用（如图片不适合抠图、模型没下载成功）必须落回可用行为**并给出提示**，不允许「点了开关没反应」。
