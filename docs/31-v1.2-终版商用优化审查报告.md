## 2. 算法逐项核验

### E1 · 网格主导色采样重构（`downsample.ts`）
- `downsampleDominantV2`：Lab 10×12×12 桶（1440）、稀疏回退（n<4 → average）、空桶平滑、确定性 argmax（并列取小 key）。✓ 桶定义、回退阈值、默认 linkage 均符合 docs/28 §2.3/§2.4。
- ⚠️ **P3-A（与 spec 偏差）**：空桶平滑的邻接权重公式 `(offset===0 ? WEIGHT[i] : 1-WEIGHT[i])` 在 `WEIGHT=[1,0.5,0.5]` 下：明度方向偏移（dl=±1）权重恒为 0，a/b 方向偏移权重恒为 0.5。**净效果**：插值只在同一 L 桶（dl=0）内、以统一 0.25 权重混合 a/b 邻桶，而设计意图“明度方向权重高”（L 邻桶权重 1）未实现。结果仍确定、取 dominant 色，但“消除桶边界跳变”的意图只部分落地。
- **处置**：属实现-规格偏差，不影响验收输出（实测更干净、确定）；列为观察建议，非缺陷。

### E2 · 低饱和小特征保护（`chromaFeatures.ts` + `features.ts`）
- `classifyChromaFeature`：C 阈值 0.10 判彩色/低彩、彩色占比 0.02–0.45 或 hue 分裂、形状复用 dot/vline/hline、`CHROMA_DOT_MIN_TOTAL=3` 放宽成簇、特征簇均值回采（`meanRgbTuples`）。✓ T33 目标（粉点 vs 肤色、小瞳距）可命中。
- ⚠️ **P3-B（与 spec 结构偏差）**：docs/28 §3.3 以 **hue 环向聚类**为主，实现以 **colored-vs-lowChroma（C 阈值）**为主、hue 分裂为辅。两个分支均被真实用例覆盖（粉点-白→colored 分支；额点-肤色→hue 分支）。功能达标，结构与伪代码略异。
- **接入安全**：`classifyRegion(...) ?? classifyChromaFeature(...)` 保证每格至多一个候选，不与亮度特征/边界仲裁冲突；protect 占用共享上限。✓

### E3 · 连通域色块合并（`merge.ts` + `pipeline/index.ts`）
- `mergeAdjacent`：4-邻连通域标记 → 按 (size asc, color asc) 排序 → 3..40 格、跳过 protect/空格、目标取邻接触次最多且 ΔE≤6 的已用色、整块并入；单遍不迭代、确定性（并列取小 color）、目标恒用已有色板索引（不新增色号）。✓ 与 `labelComponents`/`speckleCleanV2` 复用一致。
- **接入**：`mergeEnabled = featuresEnabled && mode==='dominant' && !postActive`，置于 regionClean/speckle 之前。语义上等价“照片默认路径”；cartoon/线稿（postActive 或 features 关）不触发。✓ 符合“仅照片默认路径、不改变其它模式输出”。

### E4 · 主体边缘收敛（`features.ts`）
- `soft` 候选复用 boundary 仲裁循环、`SOFT_MARGIN=2.0`；触发为块状平衡 + ΔY∈[SOFT_MIN_Y(0.03), BOUNDARY_DE_Y(0.15))，低对比；两侧贴邻才改写；不写 protect。✓ 与 v1.2.1 高对比 boundary 互补。
- **注意（观察）**：`classifyRegion` 的亮度跨度下限从 `FEATURE_CONTRAST_MIN(0.1)` 放宽到 `SOFT_MIN_Y(0.03)`，使更多低对比平坦格进入候选；但平坦格两半均值相近、邻域 dF≈dM → margin 不满足 → 保留 base，故安全。确定性保持。

### E5 · CIEDE2000 加权匹配（`ciede2000.ts` + `match.ts`）
- `ciede2000Weighted`：完整复算 kL/kC/kH 加权项；默认 {1,1,1} 退化为 `ciede2000`。`matchGridDetailed` 对 `C*<LOW_CHROMA(25)` 的格走 `nearestPaletteIndexWeighted({kL:0.85,kC:1.05,kH:1.15})`，否则走原 `nearestPaletteIndex`。✓ 不改原 `ciede2000`/`nearestPaletteIndex` 签名。
- ⚠️ **P3-C（可维护性）**：`ciede2000Weighted` 与 `ciede2000` 复制了同一整套 CIEDE2000 中间量（约 70 行）。按 docs/28 §6.3 不得改原函数，故需新函数；但两副本需人工保持同步，建议后续用共享参数化内核（不改外部签名时）。`color-weighted.test.ts` 覆盖权重=1 等价浅色排序。✓

## 5. 性能核验

- docs/30（worker 内，120×120 / 1104×1104 兔子 / 14400 格）：采样+特征 781.2ms、加权匹配 230.4ms、合并 6.3ms，**合计 1017.9ms ≤ 2s 达标**。
- 本复核关注点：**E1 采样+特征占 781ms（76%）**，是 docs/29 §3 预算里被低估的一环（docs/28 §2.5 预估采样 ~120–160ms）。绝对耗时达标，但若未来源更大/格数更多，建议优先缓存每像素 Lab（E1/E2 各算一次）。
- 移动端：默认路径转换在工作线程，主线程不阻塞（docs/02 §6）；120×120 单次 1.0s，无肉眼卡顿门槛（>100ms 需标注，见 docs/29 §3 口径）。
