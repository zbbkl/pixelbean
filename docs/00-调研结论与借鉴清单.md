## 2. 色表数据：唯一许可证安全链路

- **`maxcleme/beadcolors`（MIT，commit 94b9999）的 `gen/v1/mard.csv`（291 行 MARD 色）** 是全部调研中唯一可确认安全再分发、且已有人（bead-grid-studio）做过"快照 + SHA-256 校验"示范的数据源。
- Zippland 的 291 色映射（MARD/COCO/漫漫/盼盼/咪小窝 5 国产体系）在 AGPL 作品内；Pindo 的 8 品牌 JSON 均标注 `license:"community"`，无法证明可自由再分发；pbdx 无许可证。→ **一律不作为数据来源**。
- Pindo 的 Perler "P01–P70"、Artkal "S01–S35" 是**社区自造编号，不是官方色号**，引用时必须注意，不能当官方数据宣传。
- 详见 `docs/04` 的最终数据策略。

## 3. 对 PixelBean 的 12 条设计决策（综合三家旗舰经验）

1. **匹配用 CIEDE2000（或 Oklab ΔE）**，弃 RGB 欧氏距离；色板加载时把每色预转 Lab 并缓存，逐格只算一次距离，带阈值提前退出。
2. **默认不开抖动**；Floyd–Steinberg 做成可选开关（要就做完整版，不做名存实亡的占位）。
3. **降采样默认 linear-RGB 面积平均**（sRGB γ 解码→线性平均→编码），把"主导色"与"edge-aware 保轮廓"做成可选模式；**不用 canvas `drawImage` 缩放**（逐格按像素采样才可控）。
4. **色表数据与代码彻底分离**：独立 JSON + 编译/校验脚本，运行期按品牌按需加载；数据内带 provenance（来源+许可证+版本）。
5. **限色不用"取前 N"**：按用量取前 N 之外，保护最暗/最亮/最饱和等关键色，优先淘汰低饱和"泥灰"。
6. **每色用稳定字符串 id（`brand-code`）**，JSON 内不依赖数组下标；设透明/白/黑锚点概念 + "不参与匹配的透明格"。
7. **网格语义 = "长边格数 + 锁宽高比"**；绝不非均匀拉伸；常用底板尺寸做成预设（如 29×29），支持留空行拼接大图（v1.1）。
8. **内容分类处理**（照片/线稿/文档走不同默认参数）+ 小网格如实提示"细节有损"，是差异化卖点。
9. **纯前端 Worker 转换管线**，版本化工程 JSON（不内嵌原图）+ 可撤销操作；算法核心抽成 **DOM-free 纯模块 + golden fixture 确定性测试**（禁随机）。
10. UX 借鉴：逐色上色助理 / 专注模式、单色高亮、放大镜、可编辑网格（画笔/橡皮/取色/撤销重做）、草稿本地恢复。
11. 导出：施工图 PNG（逐格色号+坐标+辅助线）、**UTF-8 用量 CSV**（可勾选完成度）、打印用样式表；PDF 可后置（浏览器打印或 jspdf）。
12. 工程纪律：**拒绝 135–264KB 单文件巨兽**（Zippland page.tsx / bead-grid app.js 都因此产生架构债，作者自认正在重构）；README/注释必须与代码同步。

## 4. 避坑清单（别人踩过的）

- 脏数据：Zippland 根 CSV 存在 `"56/56"`、`"157/70"` 两变体挤一格。
- README 算法章节与代码脱节（Zippland 声称 RGB 欧氏，实为 Oklab）。
- 半成品功能：Pindo 的 `ordered` 抖动是占位返回原像素。
- 数据生成流程分裂：Pindo 的编译脚本只对齐 3 家品牌，另 5 家大文件未纳入脚本。
- 大网格/高缩放吃内存 → 需要像素上限保护与可取消的转换。
- 屏幕色 ≠ 真实豆色：**图纸的核心价值是"每格标官方/社区色号"**，用户按号拿豆；不要承诺颜色所见即所得，可加色差免责说明。
