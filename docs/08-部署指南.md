# 08 · 部署指南

> PixelBean 是纯前端静态站点（Vite + React + TypeScript），`npm run build` 产出完全自包含的 `dist/`，可部署到任意静态托管。无后端、无账号、无运行时服务端依赖。

## 1. 系统要求

| 项 | 要求 |
|---|---|
| Node.js | **≥ 18.0.0**（Vite 6 官方下限：`^18.0.0 \|\| ^20.0.0 \|\| >=22.0.0`）；推荐 20 LTS 或 22 LTS。本仓库实测于 Node v24.20.0 / npm 11.19.0 |
| npm | 随 Node 附带；本仓库使用 lockfile（`package-lock.json`） |
| 浏览器（运行期） | 现代 Chrome / Edge / Firefox / Safari 最新版。依赖的能力：ES2020、Web Worker（`{ type: 'module' }`）、`createImageBitmap`、`Canvas 2D`、`OffscreenCanvas`（可选降级） |
| 构建期磁盘 | 依赖安装约数百 MB（`node_modules/`） |

> 运行期无需 Node：`dist/` 是纯静态文件，浏览器直接打开或由任意静态服务器托管即可。

## 2. 构建产物

```bash
npm install
npm run build          # = generate:palettes + tsc --noEmit + vite build
```

产物结构（关键点：`index.html` 内资源均为**相对路径**，因为 `vite.config.ts` 已设 `base: './'`）：

```
dist/
├─ index.html
├─ favicon.svg
├─ samples/            # 内置示例图（照片/像素角色）
└─ assets/
   ├─ index-*.js       # 主 bundle（含 React）
   ├─ index-*.css
   └─ convert.worker-*.js   # Web Worker 转换线程（独立 chunk）
```

### 关键：`base: './'` 已配置，无需改仓库路径

`vite.config.ts` 中 `base: './'` 让所有资源（JS/CSS/favicon/示例图）都走相对路径，因此**无论部署在域名根、GitHub Pages 子路径（`/pixelbean/`）还是自定义子目录，都能直接工作，不会出现资源 404**。这是本项目对「GitHub Pages base path 坑」的根治方案；若你改用 `base: '/pixelbean/'` 之类的绝对路径，则每次换部署路径都要改并重 build，不建议。

## 3. 部署方式一：GitHub Pages

项目仓库 `zbbkl/pixelbean`。两种做法任选其一。

### 3.1 手动推 `dist/` 到 Pages 分支

```bash
npm run build
# 将 dist/ 提交到 gh-pages 分支（或用第三方工具）
git subtree push --prefix dist origin gh-pages
```

在仓库 `Settings → Pages` 里把 Source 选为 `gh-pages` 分支根目录即可。

### 3.2 GitHub Actions（推荐，全自动）

新建 `.github/workflows/deploy.yml`：

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npm run build
      - uses: actions/upload-pages-artifact@v3
        with: { path: dist }
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

访问地址：`https://zbbkl.github.io/pixelbean/`（子路径，`base: './'` 保证资源正确加载）。

## 4. 部署方式二：Vercel

1. 把仓库导入 Vercel（或 `vercel` CLI 登录后 `vercel`）。
2. 构建配置：
   - Build Command：`npm run build`
   - Output Directory：`dist`
   - Install Command：`npm ci`（默认）
3. 无需任何环境变量；`base: './'` 对 Vercel 的域名与预览子域名均兼容。

## 5. 部署方式三：Nginx

把 `dist/` 内容放到站点根目录，配一个 SPA 回退（本项目是单页，`index.html` 是唯一入口）：

```nginx
server {
    listen 80;
    server_name pixelbean.example.com;
    root /var/www/pixelbean;
    index index.html;

    # 静态资源直接命中；其余路由回退到 index.html（防止子路径刷新 404）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 长缓存带 hash 的静态资源（文件名含 hash，可安全强缓存）
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
```

## 6. 常见问题（FAQ）

### 6.1 GitHub Pages 打开后白屏 / 资源 404？

- 确认 `vite.config.ts` 是 `base: './'`（本项目已是），并**重新 `npm run build`**。
- 确认 `dist/index.html` 里的 `<script src>` 是 `./assets/...` 相对路径（而不是 `/assets/...`）。
- 若部署在非根路径，浏览器地址栏应带仓库名（`/pixelbean/`）。

### 6.2 直接刷新子路由 404？

本项目是单页且路由极简（只有首页，无前端路由），Nginx 用上面的 `try_files` 即可；GitHub Pages / Vercel 对 SPA 默认回退到 `index.html`，通常无需额外处理。

### 6.3 图片会外传吗？有隐私风险吗？

不会。所有转换都在**浏览器本机**（Web Worker + Canvas）完成，`dist/` 里没有任何请求上传图片的后端代码。图片不出本机。

### 6.4 需要离线 PWA / Service Worker 吗？

**v1 不需要。** 本项目未配置 PWA（无 service worker、无 manifest）。离线能力仅限：草稿与自定义色表存 `localStorage`，刷新可恢复；但首次加载 HTML/JS/示例图仍需网络。若未来要离线，可再加 `vite-plugin-pwa`（属 v1.x 路线图，不在本版范围）。

### 6.5 为什么示例图/色表要随包分发？

示例图在 `public/samples/`，色表编译进 `src/generated/palettes.ts`（由 `data/scripts/build-palettes.mjs` 生成）。两者都是静态资源，随 `dist/` 一起部署，无运行时网络请求。

### 7.1 线上现状

| 项 | 值 |
|---|---|
| 服务器 | `39.104.21.103`（SSH 别名 `fwq`，root） |
| 站点根 | `/var/www/pixelbean/` |
| 访问地址 | <http://39.104.21.103/pixelbean/>（**子路径**、**HTTP**） |
| Nginx | 1.28.3；站点配置在 `/etc/nginx/sites-available/mingli-ip`（`listen 80 default_server` 内的 `location /pixelbean/ { alias /var/www/pixelbean/; }`） |

### 7.2 部署步骤（可复现）

```bash
# 1) 本机构建（会自动 generate:palettes + tsc --noEmit + vite build）
npm run build
#    确认产物含模型：dist/models/isnet-general-use-int8.onnx（44.2MB）。

# 2) 打包并上传
tar -czf /tmp/pb-dist.tgz -C dist .          # Windows: 用系统自带 tar.exe
#    上传到服务器 /tmp/pb-dist.tgz（scp 或 DSH 的 ssh_upload）

# 3) 服务器上：校验 → 暂存 → sha256 门禁 → 备份 → 切换 → 验证
set -e
rm -rf /var/www/pixelbean.new && mkdir -p /var/www/pixelbean.new
tar -xzf /tmp/pb-dist.tgz -C /var/www/pixelbean.new
test -f /var/www/pixelbean.new/index.html
exp=f1b1c6f7656e532627697afc989d953be1e7ef8f55a718f3611e8c9fd50cdef7
got=$(sha256sum /var/www/pixelbean.new/models/isnet-general-use-int8.onnx | cut -d' ' -f1)
[ "$got" = "$exp" ] || { echo "SHA256 不匹配，中止"; exit 1; }   # 门禁：不匹配就绝不切换
mv /var/www/pixelbean /var/www/pixelbean.bak.$(date +%s)
mv /var/www/pixelbean.new /var/www/pixelbean
chmod -R a+rX /var/www/pixelbean
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1/pixelbean/
```

### 7.3 回滚

```bash
# 列出备份，挑一个换回去即可（切换是两次 mv，回滚同样只动目录，无需改 nginx）
ls -d /var/www/pixelbean.bak.*
mv /var/www/pixelbean /var/www/pixelbean.broken.$(date +%s)
mv /var/www/pixelbean.bak.<时间戳> /var/www/pixelbean
```

### 7.4 部署这台机器必须知道的三个坑（都踩过）

1. **子路径 + 绝对路径会打错目标**：本站挂在 `/pixelbean/`，任何 `/models/...` 这类**以 `/` 开头**的资源路径都会请求到**域名根**（那里是另一个站点）。
   ⇒ 模型路径必须**相对**资源基址解析：主线程把 `document.baseURI` 传给 worker，worker 用 `new URL('models/...', assetBase)`。
   （`base: './'` 已保证 JS/CSS/示例图正确；AI 模型路径是 2026-09 部署时才暴露的同类问题。）
2. **HTTP 下两个浏览器能力同时失效**（本地测试**永远测不到**，因为 `localhost` 是安全上下文）：
   - `crypto.subtle` 不存在 ⇒ 前端降级为**只校验模型字节数**并 `console.warn`（同一个明文 HTTP 通道上，哈希本身也没有额外保护价值）；
   - `caches`（Cache Storage）同样限定安全上下文 ⇒ **模型缓存失效，每次都重新下载 44MB**。
   **实测证据（2026-09 线上验收 11/11 通过，但记录到）**：
   ```
   warning: [AI 抠图] 当前不是安全上下文（HTTPS/localhost），无法做 sha256 校验，改为仅校验文件大小。
   关闭态 2610 格 → AI 态 1462 格（用时 337s）；二次开启同样 337s（未命中缓存）
   ```
   ⇒ **强烈建议给该站点配 HTTPS**（本机 certbot 已给 `jihe.pp123.cloud` 签过证书，可照做）。配好之后：sha256 校验恢复完整、模型本地缓存生效（第二次起约数秒）。
   注：加了 HTTPS 后仍建议做一次带宽优化（见第 3 点），否则**首次**下载依旧要等。
3. **上行带宽是体验瓶颈**：实测约 142 KB/s ⇒ 用户首次启用 AI 抠图要**等约 5 分钟**（界面有百分比进度与缓存，第二次起走本地缓存，不再下载）。
   ⇒ 建议把 `models/isnet-general-use-int8.onnx` 放到 **CDN / 对象存储**（或换更大带宽的机器），把首下时间压到秒级；代码侧只需把模型改成绝对 CDN 地址（`AiModelSpec.path`）或在站点前面挂 CDN。
