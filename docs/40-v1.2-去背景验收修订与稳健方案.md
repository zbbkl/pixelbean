# 40 · 去背景验收不通过后的修订决策与方案（DeepSeek 规格）

> 流程：DeepSeek Harness（规格）→ **Codex（实现）** → Claude Code（复核）。
> 触发：Claude Code 对 `docs/37` 去背景改动的独立验收**结论：不通过**（默认开启吞掉近白主体），报告见 [`docs/39`](39-v1.2-去背景验收报告-ClaudeCode.md)。
> 本文是 **DeepSeek 对验收结论的采纳 + 修订规格**：先给「止血清零风险」的 A 方案，再给「若要默认开启」需换算法的 B 方案（分级、可回退、带回归门禁）。

## 0. 结论与决策

1. **接受 `docs/39` 不通过结论**。`subject.ts` 的「边界背景色 + 梯度停止洪水」对**白底 + 白身 + 软阴影**主体是**结构性失效**，不是 `tol/edge` 调参可解（报告已扫描 `tol×edge` 网格，无「能保头部」的组合）。
2. **立即止血（A 方案，最低风险）**：
   - `removeBackground` 默认值改回 **`false`**（照片/卡通预设同样置 `false`），保留手动开关。这样默认观感**严格回到上一版**（已验证「关闭 = 逐格等同上一版」，hash 一致）。
   - 新增**可信度兜底**：`extractSubject` 返回 `reliable` 与 `subjectRatio` / 最大连通域占比；当抠图不可信（比例过低或主体不连通）→ **回退全主体、不做抠图**。同时修掉验收 P2-2「纯色图 → 空图纸」。
   - 补**回归门禁夹具**：把 `rabbit-source.png`（或其降采样版）纳入 fixtures，断言「头部矩形区 mask 覆盖率 > 0.8、主体最大连通域占比 > 0.9、开启 ≠ 吞主体」。
3. **若要默认开启（B 方案，稳健去背景）**：必须**换算法**而非调参——用**多尺度结构梯度引导**的洪水/主体分割（或主体侧线索 / alpha matting），并以同一门禁验证通过后才允许默认开启。B 方案因带更多算法/不确定性，**分级为独立后续任务**，不纳入本次最小修复。
4. **同步文档**：`docs/38` 的「通过」结论不成立，需按本报告更正；README 状态由「✅ 已实现并自测」改为「⚠️ 验收未通过，回退默认关闭」；`docs/37 §4` 的「默认开关」配置按本文件修正。

## 1. 失败根因（采纳 `docs/39` 证据）

- **颜色距离不再有效**：`ΔE(px, bgColor) ≤ tol` 对**白底与白身一律成立**——报告实测主体反而**更接近**边界背景色（头顶 ΔE≈3.87 < 背景四角 11.53）。
- **梯度停止失效**：柔光 3D 渲染的软过渡使**单像素梯度永不超** `edge`（`edge` 2→18，头部覆盖 0.185→0.176），形同虚设。
- **结果**：洪水从四边吞掉白色身体（头/颈/躯干 → 判背景），只留彩色/深色（眼、耳尖、米色腹部、腿部灰影）——**去背景变「去主体」**；且灰接触阴影反被当主体。
- **不存在**能同时保住头部的 `(tol, edge)` 组合（报告已网格扫描）。

> 归因一句：**这类图的「主体比背景更接近背景色 + 无强边缘」使颜色洪水天然失效**，必须依赖**空间结构/主体侧**线索，或 alpha matting。

## 2. 修订方案 A（立即、安全、确定性）—— 建议先落这个

### A.1 默认关闭（止血）

- `src/app/options.ts` / `defaultSettings`：`removeBackground: false`。
- `src/core/post/modePresets.ts`：`photo`/`cartoon` 预设 `removeBackground: false`（`lineart`/`pixel` 本就 false）。
- 保留 UI 手动开关（`ParamPanel.tsx`），仍是「一键去背景」可触达。
- 效果回归：关闭态 = 上一版（`docs/39` §5 已验证逐格 0 差异）。

### A.2 可信度兜底（治 P2-2 + 防吞主体）

`src/core/pipeline/subject.ts`：

```ts
export interface SubjectResult {
  cells; mask; bbox;
  reliable: boolean;                 // 抠图是否可信
  subjectRatio: number;              // 主体占比
  largestComponentRatio: number;     // 最大主体连通域占主体比例
}
```

**判定不可信（回退全主体，mask 全 1、不抠）**，满足任一：
- `subjectRatio < RATIO_MIN`（建议 0.15）；或
- `largestComponentRatio < COMP_MIN`（建议 0.55，即主体被打碎）；或
- `bbox` 覆盖整幅 ≥ `FULL_RATIO`（建议 0.98，即主体几乎占满、无背景可去）。

**接入**（`pipeline/index.ts`）：`extractSubject` 返回 `reliable=false` 时**不再**调用 `downsampleMask`/`clearBackgroundCells`，直接按「未去背景」走现有管线（等价 `removeBackground=false`），从而**不可能再吞主体或产空图纸**。

### A.3 回归门禁（必做，替换 `tests/unit/subject.test.ts` 的硬边合成覆盖）

- 新增夹具：`rabbit-source.png`（`docs/39` 用到的 1104×1424 样例）或其 220×284 降采样版。
- 断言：
  - 开启态**头部矩形区**（头/耳区域，约 bbox 上部 1/3）mask 覆盖率 `> 0.8`；
  - 主体**最大连通域占比 `> 0.9`**；
  - **开启态主体像素数 ≥ 关闭态 × 0.9**（不吞主体）。
- 现有硬边用例保留（验证这类图正常）。

## 3. 修订方案 B（稳健去背景，若要默认开启）—— 分级为独立后续任务

> 因带更复杂算法与更多不确定性，**不纳入**「最小修复」；仅在满足门禁后才允许默认开启。

### B.1 多尺度结构梯度引导的洪水分割

颜色距离放弃作为「唯一判据」，改用**结构梯度屏障**，并在**多个尺度**上取边缘脊：

```text
edgeStrength(p) = max_{s ∈ {2,4,8}} ΔE76( mean_s(p) , ring_s(p) )
   // mean_s：s×s 窗口平均；ring_s：窗口外一圈平均。软轮廓在粗尺度也能成脊。
flood(p) 判为背景：
   ΔE(px(p), bgLocal) <= tol   AND   edgeStrength(p) <= edgeScale
   // tol 建议 6~8（收紧，不再靠颜色吞主体），edgeScale 建议 12
```
沿用 A.2 的可信度兜底；凡 ROI/连通域不达标即回退。

### B.2 主体侧线索（可选增强）

- 取**最大主体连通域**作为候选主体（忽略散点）；
- 或在洪水后做「主体区域从较暗/较彩一侧向内生长」，仅保留被主体轮廓包围且不与边界连通的**最大连通域**。

### B.3 门禁（不通过不得默认开启）

- 兔子图：头部矩形区掩码覆盖 `> 0.8`、主体最大连通域占比 `> 0.9`、开启 ≠ 吞主体；
- 首屏 `sample-photo.jpg`：开启态不得出现「透明锯齿边框 + 背景残块环绕」；
- 纯色图：不产空图纸（由 A.2 兜底）。

### B.4 上限声明

若 B 系列门禁仍无法稳定达成（白身白底 + 强柔光模糊），应**明确承认此类图需 alpha matting / 学习式抠图**（`rembg` 一类），并将其列为**单独大任务**；在 `docs/00` 许可红线内只参考思路、不引入受限代码。
