## 0. 变更总览与兼容纪律

### 0.1 核心命题

用户提供的原图 → 78×78 产出图暴露三类**商用不可接受**缺陷：

| 缺陷 | 表现 | 根因（已实测/目检确认） |
|---|---|---|
| **画面发虚** | 白身皮肤混入灰、边缘柔、整体像蒙雾；色块颜色不干净 | 默认 `average` 降采样把边界/背景/高光平均成"中间脏色"；再经最近邻匹配落到非两侧的邻近色 |
| **特征丢失** | 瞳孔黑色消失、额头红点消失、耳内侧粉变灰白 | 高对比小特征在 `average` 里占比过低被洗掉；特征保护（`features`）虽默认开，但其识别阈值对**低饱和粉**（额点/耳尖）与小瞳距不敏感 |
| **色块杂乱** | 地面/背景出现灰绿块、细碎过渡色、孤立噪点；色数偏多 | 均值池化产生大量中间过渡色（实测兔子 13 色 vs 主导色 8 色，孤立噪点 329→244；卡通 27→5 色、542→124） |

本版以**管线级采样重构为核心**，配合特征保护增强、连通域合色、轮廓收敛、色板权重微调，把输出提升到"块面干净、边缘硬、特征完整"的商用级。

## 2. E1 · 网格主导色采样重构（`downsample.ts`）

### 2.1 目标与问题

现有 `downsampleDominant`：把网格内每个像素的 linear RGB 量化到 6bit/通道桶（64³ 桶），取**频次最高桶**的线性均值作为该格色。

**缺陷**（实测 + 目检）：
1. **linear 空间 64³ 桶**对明度分布不均：暗部（L*<20）与浅色（L*>80）桶内像素跨度大，导致暗部/浅色区"同一个桶里混入不同色相"，区块被过分割→产生分块伪影。
2. **winner 桶取平均**：当桶内两簇不同色时，平均又回到"中间脏色"（治标不治本）。
3. **默认未启用**：photo/cartoon 仍走 `average`。

### 2.2 参考实现逻辑（仅思路，代码自研）

对标 pixilation（主导色采样 + 边缘保留）与 PixelIt（中值切割量化）：主导色应在**感知空间**量化，且对空桶做平滑插值以消除"桶边界骤变"。

> 注意：PixelIt 的中值切割是"全局调色板量化"，与本项目"逐格主导色采样"目标不同——本项目网格是**固定底板网格**，不是色板收缩，故采用"逐格感知主导色 + 空桶平滑"，而非全局中值切割。谨防误解。

### 2.3 算法伪代码

```
downsampleDominantV2(image, W, H, bg, adjust, {barrelSize=24, emptySmooth=0.5}):
  // 桶定义：把 sRGB→Lab，再按 L*(10)、a*(12)、b*(12) 量化成 10×12×12 桶。
  //   —— 感知空间用 a*/b* 色度（而非 linear RGB），暗部/浅色区不再因明度跨度而分裂色相。
  for each grid cell (gy,gx):
    region = 该格覆盖的源像素区间（沿用 downsample 的 x0..x1/y0..y1 公式）
    buckets = Map<key, {count, sumL, sumA, sumB}>
    for each pixel in region:
      rgb = effectiveRgb(源像素, bg, adjust)      // 复用 backgroundRgb + adjustRgb
      lab = srgbRgbToLab(rgb)
      key = (round(L*|barrelSize*(10/100))<<16) | ...
             // 简化：labels = [10,12,12]，key = l*12*12 + a*12 + b（线性索引，桶总 1440）
      buckets[key] += (1, sumLab…)
    // --- 插值：对每个桶给一个"频率"；对空桶用邻接非空桶加权（emptySmooth 控制插值强度）---
    //   消除"桶边界骤变"（真实图像素在桶边界附近抖动会导致格与格颜色跳变）
    dominant = argmax_{key} ( count[key] + emptySmooth * Σ_{邻接桶 count} * 邻接权重 )
    // 若区域像素极少（n < NEARLY_EMPTY_PX=4）或全为背景 → 回退 average（避免稀疏区抖动）
    取 dominant 桶的 Lab 均值 → sRGB 字节；写 out[cell]=rgb, alpha=255
  return out
```

- 关键差异点（相对现有 `downsampleDominant`）：
  - 桶在 **Lab** 而非 linear RGB（10×12×12，1440 桶），消除明度跨度导致的色相分裂。
  - **空桶插值**：以 `emptySmooth` 加权邻接桶频率，避免桶边界色跳变（"软边"观感根源之一）。
  - **稀疏区回退**：region 像素 < 4 或全背景时用 `average`，避免极小区域抖动。

### 2.4 参数表（默认值 + 边界）

| 参数 | 语义 | 默认/取值 | 依据 |
|---|---|---|---|
| `barrelSize` (dims L×a×b) | Lab 量化桶数 | `[10,12,12]`（index 1440） | a*/b* 色度人眼可分度近似；10 明度层足够，12 色度层在彩度不高区域不产生过分割 |
| `emptySmooth` | 空桶插值强度 | `0.5` | 0=纯硬分配（保留现有分块伪影）；1=强插值（过度平滑把细节抹掉）；0.5 均衡 |
| `WEIGHT_DIM` | 插值邻接桶权重 | `[1,0.5,0.5]`（明度方向权重高） | 明度相邻更应连续 |
| `NEARLY_EMPTY_PX` | 稀疏/全背景回退阈值 | `4` | 像素太少无统计意义 |
| `defaults` | 模式默认 | photo/cartoon=`dominant` | §实测 |

### 2.5 性能

- 每格一次像素扫描 + Lab 转换；桶数固定 1440，找 argmax 常数。总开销 ≈ 逐格 `srgbRgbToLab`（比现有 linear 桶多一次 Lab 转换）+ 固定 1440 桶的比较。
- 实测：`dominant` 采样在 1104×1424 源、60×78 网格上 sampleMs≈64ms（vs average 28ms），匹配才是大头（≈250ms）。Lab 桶化 + 固定桶比较将使 sample 增到 ~120–160ms，仍在 docs/19 Q4"同数量级"预算内（<500ms 单次），可不做硬超时断言；若需优化可预计算每像素 Lab（一次）并复用，见 §7 FAQ。

## 3. E2 · 关键特征保护增强（`features.ts`）

### 3.1 问题

现有特征识别基于**亮度双类分裂 + 形状分类**（dot/vline/hline），对亮度对比强的特征（深瞳、黑线、白高光）有效。但对**低饱和色相特征**失效：
- **额头粉红小点**：与肤色亮度接近、色相不同 → 双类按亮度分裂失败 → 被当背景/肤色洗掉。
- **耳内侧粉**：浅粉 vs 白，亮度差小、彩度差小 → 同样被判定非特征。
- **小瞳距眼睛**（如兔子两只眼距离近、瞳孔小）：`FEATURE_DOT_MIN_TOTAL=4` 才成簇，且阈值在低彩度下过严。

### 3.2 参考逻辑

perler-bead-generator 与 pixilation 的色块合并/主导色在"小色块融入主区"上依赖**彩度/色相连续性**而非纯亮度。E2 借鉴"以色相+彩度判特征"而非仅亮度。

### 3.3 算法伪代码（在 `classifyRegion` 后追加"彩度特征"通道）

```
// 新增：彩度小特征候选（在原亮度双类失败或 share 边界时启用）
classifyChromaFeature(regionPixels, regionW, regionH):
  n = 像素数; if n < FEATURE_REGION_MIN_PX(8): return null
  // 计算区域彩度统计
  for each pixel: lab = srgbRgbToLab(rgb); C = hypot(a,b); hue = atan2(b,a)°; L = lab[0]
  // 找"色相离群簇"：把像素按 hue 聚成 2-3 簇（用 hue 距离，环向），取最小簇
  clusters = 按 hue 环向聚类(2 簇, 阈值 CHROMA_HUE_GAP=25°)
  small = 最小簇; big = 其余并集
  share = |small| / n
  // 判据：彩度差 + 色相差 足够（不需要亮度差）
  dC = |meanC(small) - meanC(big)|;  dHue = 环向色相差(small,big)
  if share ∈ [0.02, 0.45] && (dC >= CHROMA_DC_MIN(0.12) || (dHue >= 25° && meanC(small) >= CHROMA_DOT_MIN(0.10))):
    bbox 检形 → dot/vline/hline 复用现有形状判定；否则 return null
  return { kind, meanSrgbF=small 均值, meanSrgbM=big 均值 }
```

- **接入**：`downsampleWithFeatures` 在遍历候选时，对"亮度 candidate == null"的格再调 `classifyChromaFeature`；命中则并入候选集。
- **成簇与写色**：复用现有 dot 成簇逻辑（`FEATURE_DOT_MIN_TOTAL` 对彩度特征放宽到 **3**，新增 `CHROMA_DOT_MIN_TOTAL=3`）；写色不再只取单格，而是**取该特征簇的平均色**（见 3.4"特征均值回采"），避免单格噪声。
- **protect 掩码**：命中即 `protect[g]=1`，与既有特征语义一致（H1 不并、H2 仅池内收敛、H3 入保护集）。

### 3.4 特征均值回采（E2/E4 共用，新增小函数）

> 问题：现有特征写色用 `candidate.meanF`（少数侧均值）。若少数侧只覆盖 1–2 像素，均值即为该像素色，对"低饱和粉点"可能因 JPEG 噪声偏灰。
> 改进：特征格颜色 = **该特征在所有被识别格上的特征侧均值**（跨格回采），或该特征的源区域中"特征侧像素的色度 = 周围主体的色相 + 特征色度偏移"重构。为保持确定性，采用**跨格特征簇平均**。

```
writeFeature cluster: 
  meanF_cluster = mean(所有成员格 candidate.meanF)
  for each member: baseCells[member] = meanF_cluster; protect[member]=1
```

### 3.5 参数表

| 参数 | 值 | 依据 |
|---|---|---|
| `CHROMA_HUE_GAP` | 25° | hue 环向簇距离阈值（低于此视为同色相） |
| `CHROMA_DC_MIN` | 0.12 | 彩度差下限（a*²+b*² 归一化） |
| `CHROMA_DOT_MIN` | 0.10 | 低饱和特征的最小彩度 |
| `CHROMA_DOT_MIN_TOTAL` | 3 | 彩度特征成簇格数下限（比亮度特征 4 放宽，因低饱和点常更小） |

## 4. E3 · 连通域色块合并（`src/core/post/merge.ts`）

### 4.1 目标

现有 `speckleCleanV2` 只清**孤立小域**（≤N 格、贴附主色强）；`regionClean` 只做**单遍格级**多数修正。两者都不处理：
**"同一色块内部，被 1–2 格异色分割开的同色小区"**（如白色身体里一粒灰过渡色），以及**"大色块边缘的细碎同色系杂色"**。

E3 用**连通域邻接合并**把这类"同色系小面积杂色"并入邻接主块，块面干净。

### 4.2 参考逻辑

perler-bead-generator 的"色块合并"在量化后把面积过小、与邻近块色差小的块合并掉；PixelIt 中值切割的"后合并"。E3 借鉴"区域级、按邻接关系 + 色差"合并。

### 4.3 算法伪代码

```
mergeAdjacent(pattern, palette, protect=null, deThr=MERGE_DE(6), minArea=MERGE_MIN_AREA(3), maxArea=MERGE_MAX_AREA(40)):
  // 连通域标记（复用 labelComponents 思路：4邻、同色同域；空格 -1 不参与）
  comps = labelComponents(pattern)
  // 排序：面积升序，color 升序（确定性）
  sort comps by (size asc, color asc)
  cells = Int16Array(pattern.cells)   // 工作副本
  merged = Set<color>
  for comp in comps:
    s = comp.size
    if s < minArea || s > maxArea: continue          // 太小=噪点交给 speckle；太大=主块不动
    if protect 覆盖 comp 任一成员: continue           // 特征/保护格不并
    // 找"最能代表该块"的邻接主色：按边界接触次数排序，且色差 <= deThr
    best = argmax by boundaryCount(boundary), 且 ΔE2000(palette[comp.color], palette[best.color]) <= deThr
    // 可选强判据：该块"贴附"主块的边数 >= 块自身与其它色接触的某个比例（避免把两色交界处的第三色强行并入某一侧）
    if best 存在:
       for each cell in comp: cells[cell] = best.color    // 整块并入
  return changed ? {...pattern, cells} : pattern
```

- **只合并纯色块**（`color == comp.color` 的整块），不合并"异色混块"（那是别的阶段）。
- **不跨越空格**：boundary 只统计 `cells[nb]>=0` 的邻接；纯浮岛（四邻全空/出界）boundary 为空 → 不并。
- **确定性**：遍历按 (size,color) 排序，并列取索引小者；单遍不迭代。
- **与 protect 关系**：含 protect=1 的块跳过（保护特征如瞳孔/细线）。
- **默认接入**：`convertPipeline` 内，仅当 `featuresEnabled`（照片默认路径）时调用，且置于 `speckleCleanV2` 之前。不改变其它模式的输出。

### 4.4 参数表

| 参数 | 值 | 依据 |
|---|---|---|
| `MERGE_DE` | 6 | 并入色差阈值（ΔE2000）；比 speckle 的 30 严，只并"同色系" |
| `MERGE_MIN_AREA` | 3 | 小于 3 格不并（交给 speckle 处理孤立点） |
| `MERGE_MAX_AREA` | 40 | 超过 40 格视为主块，不并 |
| N/A | — | 目标色恒为已用色板索引，不新增色号 |

### 4.5 性能

- 连通域标记 O(格数)；合并循环 O(组件数×邻接边)。以 MAX_CELLS=150k 计，与 speckleCleanV2 同数量级（<数十 ms）。

## 5. E4 · 主体边缘自动收敛（硬边）（`features.ts` + `outline.ts` 可选）

### 5.1 目标

当前"柔边"来自：**过渡格**（`average` 把主体与背景交界的格平均成两者中间的色）在 dominant 下虽缓解，但**主体与背景亮度接近**（白兔 vs 白背景）时主导色仍可能取到背景侧或混合侧。

E4 在采样阶段做"**主体边缘收敛**"：把属于主体/背景交界的格仲裁为更贴近**主体一侧**而非混合色，输出清晰硬边。

### 5.2 参考逻辑

Pindo 的 edge-aware 降采样、pixilation 的边缘保留——边界格优先取"区域侧"颜色。v1.2.1 已实现"**平衡双类边界格仲裁**"（`features.ts` BOUNDARY 分支），E4 在其上**追加"低对比柔边收敛"**（针对亮度接近但确有主体/背景之分的格）。

### 5.3 算法伪代码（在 `downsampleWithFeatures` 的 boundary 处理旁追加）

```
// 现 v1.2.1 boundary 仲裁只处理"高对比平衡双类"（ΔY>=0.15）。
// E4 追加：低对比但主体/背景可分的"柔边格"
// 触发：原 boundary 判据 ΔY 不足（< BOUNDARY_DE_Y=0.15），但该格与 4-邻已产出 base 的"主体/背景色"存在可判归属：
softEdgeArbitrate(g):
  M = 该格多数侧均值（亮度双类多数侧）；F = 少数侧均值
  nb = 4-邻已产出 base 色（跳过空格/越界）
  dM = mean ΔE2000(meanRGB(M), baseRGB(nb)); dF = mean ΔE2000(meanRGB(F), baseRGB(nb))
  if nb 为空: return base[g]                     // 孤立格不猜
  elif dF + SOFT_MARGIN(2.0) <= dM: return meanRGB(F)   // 少数侧(通常=主体亮面/暗面)更贴周围 → 取 F
  elif dM + SOFT_MARGIN(2.0) <= dF: return meanRGB(M)
  else: return base[g]                           // 两可 → 保留
```

- **关键**：柔边收敛**只在主体/邻域可判定**时改写（nb 非空、且一侧显著贴邻），否则保留——避免在纯渐变区引入骤变。
- **与主体边界关系**：柔边格不改写保护掩码（不 protect），因为它不是特征而是边界归属修正。
- **默认**：photo 路径（features 开）即生效；不改变 lineart/pixel（不经 features）。

### 5.4 outline 可选微调（`outline.ts`）

> v1.2.1 决定 outline 连续性微调**不并入默认**（§6.2）。本版保持**不改 outline 默认**；仅在文档层说明：若需更"硬边"，用户可开 outline（可选装饰），其输出仍为 1px、色板内深色、K+1 例外。不新增代码。

## 6. E5 · 色板映射权重（CIEDE2000 加权）

### 6.1 问题

兔子图里"浅粉耳尖 → 白/灰"、"米黄肚皮 → 白/浅灰"的误配，源于 `nearestPaletteIndex` 用 kL=kC=kH=1 的 CIEDE2000，**对色相差的惩罚不足**——浅色系之间（白、米白、浅粉、浅黄）L* 接近，a*/b* 差被未加权的距离稀释，导致误配到"更近但色相不对"的白/灰。

### 6.2 参考逻辑

CIEDE2000 支持 kL/kC/kH 权重。提升色相权重（kH）、微降明度权重（kL）能强化"色相必须对"的约束，对肤色/浅色系（a*/b* 小而重要）尤其有效（PixelIt/perler 的感知匹配思路）。

### 6.3 算法

新增 `ciede2000Weighted`（不改原 `ciede2000`，保证既有 golden 不回归）：

```
ciede2000Weighted(lab1, lab2, {kL=1, kC=1, kH=1}):
  // 复用 ciede2000 中间量（dLp/SL, dCp/SC, dHp/SH, RT）
  return sqrt( (dLp/(kL*SL))^2 + (dCp/(kC*SC))^2 + (dHp/(kH*SH))^2 + RT*(dCp/(kC*SC))*(dHp/(kH*SH)) )
```

**权重选择（肤色/浅色系优化）**：
- 默认全局：`{kL:1, kC:1, kH:1}`（退化为原 ciede2000，不改既有行为）。
- 匹配层对**浅色/低彩度**（`C* < LOW_CHROMA(25)`）的格子，采用 `{kL:0.85, kC:1.05, kH:1.15}`：
  - `kL<1` → 明度差惩罚减少（白/米白/浅灰在明度上接近，不应仅因此互斥）；
  - `kH>1` → 色相差惩罚加大（强制"浅粉→粉、浅黄→黄"，而非"浅粉→白"）。
  - `kC` 微升：彩度差也更重要（避免浅粉误配灰）。

> 权重是**经验值**：需在真实肤色/浅色图上对照调优（§8 验收 T8 记录两套权重 ΔE 排序变化）。初版按上表，若 Codex 对照发现白色系误配未改善，可微调 `kH∈[1.05,1.3]`、`kL∈[0.7,1]`，但需回归既有 golden。

### 6.4 接入

`matchGridDetailed` 内 `nearestPaletteIndex` 无法直接传权重（其签名被沿用）。**做法**：在 `matchGridDetailed` 里对每格先算 Lab，若 `C* < LOW_CHROMA` 走 `ciede2000Weighted(lab, palette.labs, {kL:0.85,kC:1.05,kH:1.15})`，否则走原 `nearestPaletteIndex`。**不改 `nearestPaletteIndex` 的既有导出签名**，新增内部 `nearestPaletteIndexWeighted`。

### 6.5 性能

- 仅对 `C*<25` 的格额外走一次加权 CIEDE2000（仍是常数 291 候选 × 每格一次）。实测采样+匹配总耗时增量可忽略（<10%）。

## 7. 下游开发 FAQ（Codex 可能疑问）

**Q1 `downsampleDominantV2` 是否替换旧 `downsampleDominant`？**
不替换：旧函数保留（供 `lineart`/`pixel` 既有行为与旧测试），V2 作为新导出，`downsample()` 的 `'dominant'` 分支改调 V2。即"dominant"语义升级为 V2，但对线稿/像素的实色图（无平衡双类渐变）输出与原基本一致（golden 若变仅允许"杂色更少"方向）。

**Q2 E2 彩度特征会不会把"渐变里的次级分区"当特征？**
不会：`CHROMA_HUE_GAP=25°` 与 `dC>=0.12`（或 `meanC>=0.10` 且色相差）双门槛，且要求 share∈[0.02,0.45]；纯渐变区色相差小、彩度差小 → 不触发。protect 上限（PROTECT_CAP=max(24,2%)）依旧约束总量（复用具逻辑）。

**Q3 E3 与 speckleCleanV2 / regionClean 会不会重复或冲突？**
- `speckleCleanV2` 处理**孤立小域**（≤N 格、贴附强）；E3 处理 **minArea..maxArea(3..40) 的同色系连通块**，两者面积区间基本不重叠。
- `regionClean` 是**单遍格级多数修正**（默认 opt-in 关）；E3 是**块级合并**（默认照片路径开）。若用户手动开 regionClean（opt-in），顺序为 merge → regionClean → speckle，均对 protect/空格安全。
- 冲突仲裁：同一格若同时被三阶段候选，优先级 protect > merge > regionClean > speckle（按管线顺序执行，先到先改，不改已改格）。

**Q4 会不会新增"无效色号"？**
不会。E3 目标色 ∈ 邻接已用色板索引；E2 特征色是源图色，最终仍经匹配到色板索引；E5 是匹配距离定义变体，不改色号集合。全链唯一可能 K+1 的仍是 outline（docs/03 §9.4）。

**Q5 性能预算？**
E1 让采样多 ~60–100ms（Lab 桶化）；E3 连通域多 <数十 ms；E5 匹配增量 <10%。以 MAX_CELLS=150k、源 ≤16M 像素为上限，单次转换仍应在 docs/19 Q4"同数量级"内（绝对数通常在几十~几百 ms）。不设硬超时断言（CI 抖动），自测记录实际值。

**Q6 确定性怎么保证？**
无随机；一切 argmax/排序并列取索引小者；桶化与插值均为纯函数；E2/E3/E4 单遍不迭代。golden 回归用整段 hash 不变。

**Q7 为什么照片默认改 dominant 而不是继续 average？**
实测（§0.1）dominant 在两张真实图上色数与孤立噪点显著更低（兔子 13→8 色/329→244 噪；卡通 27→5/542→124），块面干净、边缘硬——正是"商用级"要求。average 保留供柔和优先用户手动选。
