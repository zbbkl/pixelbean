# 04 · 色号表数据设计（Palette 数据契约）

> 这是所有色表数据的**唯一格式契约**（Schema 文件：`data/palette.schema.json`）。
> 数据策略依据：`docs/00` §2 与子代理对 pbdx / Jett-Wu / hank / beadmachine / autoclaw 的实际文件核查。

## 1. 数据模型（对齐业界最佳：pbdx 的结构设计，但完全自建数据）

单个 PaletteSet 概念 = **一个品牌 × 一种豆子尺寸 × 一套色号体系**（如 "MARD 291"、"Artkal M-Mini 221"、"Perler standard"、"Hama midi"）。

顶层文件结构（每文件一个 PaletteSet，自包含）：
```jsonc
{
  "$schema": "../palette.schema.json",
  "schemaVersion": "1.0",
  "id": "mard-291",                  // 稳定 slug，跨版本不变；运行期引用键
  "label": "MARD 291（店家通用）",
  "brand": "MARD",
  "standard": "291",                 // 色号体系名/子集
  "beadSizeMm": 5,                   // 常见 5mm；2.6mm mini 另行建 set
  "quality": "community-verified",   // official | community-verified | community-legacy
  "source": "Jett-Wu palette.ts(MIT) + maxcleme/beadcolors mard.csv(MIT, 待核) 交叉",
  "license": "MIT",                  // 该数据集的许可证（必须写明）
  "licenseNote": "数据段复制自 MIT 项目；保留上游版权声明，见 data/provenance/",
  "codeStyle": { "stripLeadingBrandChar": false, "zeroPad": 2 },   // 见 §3 显示规则
  "notes": "hex 为工程近似色，与实物存在色差；图纸以 code 为准",
  "colors": [
    { "code": "A01", "name": "白色", "nameEn": "White",
      "hex": "#FEFEFA", "rgb": [254,254,250],
      "kind": "solid", "family": "A" },
    { "code": "H1",  "name": "透明", "kind": "transparent", "hex": null }
  ]
}
```

每个颜色字段：
| 字段 | 必填 | 说明 |
|---|---|---|
| `code` | ✅ | 官方/店家色号字符串（权威标识，图纸标注用它）。可含字母（`A01`/`H1`/`P23`/`ZG01`） |
| `name` / `nameEn` | 否/否 | 中文名/英文名（可选，UI 悬停显示） |
| `hex` | 条件 | 工程近似色（**非官方色彩科学测量**）；`transparent` 类可为 null |
| `rgb` | 条件 | 与 hex 等价的 0–255 数组（可省，加载时由 hex 推导，二选一必填其一） |
| `kind` | ✅ | `solid` 实色（参与最近邻匹配）\| `special`（夜光/珍珠/金属/荧光，**默认不参与匹配**，仅用户显式选）\| `transparent`（不参与匹配） |
| `family` | 否 | 系列分组（如 A/B/C/H/M），用于按色系筛选 UI |
| `sortKey` | 否 | 可选数值排序键（如 291 全量的官方编号顺序）；缺省按 code 字典序 |

顶层 `quality` 分级（诚实标注）：
- `official`：转录自品牌官方公开表（如 Artkal 2025 官方 RGB PDF）→ 可作默认推荐。
- `community-verified`：多个独立社区源（至少两个 MIT 源）交叉核对一致 → 默认可用。
- `community-legacy`：单一老社区源、数据较旧/可信度低（如 2017 年的 Perler 51 色）→ 只在目录中可选，UI 标注"数据较旧"。

**关键红线**：
- ❌ 不从 pbdx（无许可证）、Zippland/perler-beads-ai（AGPL 链）、autoclaw（无 LICENSE + hex 编造不可信）复制任何色表数据。

- 官方转录（Artkal PDF / 品牌官网色卡）不涉及他人汇编版权，最安全，但 hex 需人工/程序从 PDF/图片取色，误差需记录。

## 3. 显示规则（色号在 UI/图纸上的呈现）

- 图纸与统计中的**权威标识 = `code`**；hex 仅用于色块预览。
- 码前缀规则：不同品牌对同一色系的写法不同（Artkal M-Mini 官方 `MA1` vs 用户俗称 `A1`；MARD 有人写 `A01` 有人写 `A1`）。处理：数据存**官方规范码**（如 `MA1`、`A01`），`codeStyle` 控制展示变换：
  - `stripLeadingBrandChar`（Artkal 类去掉前缀字母）、`zeroPad`（MARD 补零到 2 位）。
  - 展示变换**只作用于 UI/图纸文字**，不改变匹配逻辑与统计聚合键。
- `kind: special / transparent` 的颜色默认不在色板选择器里参与匹配，但在"自定义/手动"模式可见；palette 级 `notes` 里给一句"特殊/透明色默认不参与自动匹配"。

## 4. 目录与采集工作流

```
data/
├─ palette.schema.json          ← 格式契约（JSON Schema draft-07）
├─ palettes/                    ← 交付的内置 PaletteSet（每品牌一个 JSON，见 §1）
│   ├─ mard-291.json
│   ├─ artkal-m-mini-221.json   (P1)
│   └─ …
├─ provenance/                  ← 采集证据：上游文件快照 + sha256 + 版权声明
│   ├─ README.md                （每个来源：URL、commit、许可证、采集日期、转换说明）
│   ├─ jettwu-mard-221-291.csv
│   ├─ hank-beads.hex.txt
│   └─ beadmachine-colors_hama.json
└─ scripts/
    ├─ fetch-sources.mjs        （下载 MIT 源到 provenance/，记录 commit+sha256）
    ├─ normalize-to-palette.mjs （CSV/hex 表 → PaletteSet JSON；hex 归一化、code 规范化）
    ├─ crosscheck.mjs           （重叠色号跨源核对：ΔE < 10 一致，否则记录差异供人工裁决）
    └─ validate.mjs             （对 palettes/*.json 跑 schema 校验 + 断言：色数、code 唯一、
                                  求和/占比自检、无重复 hex 近似等）
```

流水线（Codex 阶段 2 的**前置子任务 2a**，产出物为 data/palettes/ 下 JSON）：
1. `fetch-sources.mjs` 下载三个 MIT 源 + （核查许可后的）beadcolors mard.csv 进 `provenance/`，记录 commit/sha256。
2. `normalize-to-palette.mjs` 生成 `mard-291.json`（主键数据集）与 Hama/Perler/Artkal 起步集。
3. `crosscheck.mjs` 对重叠色号做 ΔE 交叉核对，输出差异表。
4. `validate.mjs` + schema 校验全绿；人工抽查 10 个常见色号（白/黑/红/肤/蓝/绿…）的 hex 与实物观感。
5. 运行期加载：`build:palettes` 把启用集打包进 `src/generated/palettes.ts`（按需 import，控制体积）；`importPalette(json)` 运行时校验自定义导入（同一套 schema 与错误提示）。

**v1 保底方案**：若 P1 品牌采集超时，v1 仍可演示 = `mard-291` + 自定义色表导入（用户粘贴符合 schema 的 JSON 即可换品牌），功能链路完整，只是内置品牌少。

> **2026-09 决策记录**：阶段 2（Codex）只交付 `mard-291.json` 一个内置集（MIT 链路最稳）；Hama/Perler/Artkal/Nabbi 等全部二期。`palette.schema.json`、目录结构与 loader 契约已按多品牌就绪，二期只加数据不改代码。

## 5. 反例提醒（不要这样写数据）

- 不要用数组下标当颜色身份（色号会随增删漂移）。
- 不要给 `transparent` 编造 hex。
- 不要混入"AI 编造色"（autoclaw 的 Artkal `#E60012`=纯红就是反例）。
- 不要在同一 PaletteSet 里混两种尺寸或两个品牌。
- 不要把 provenance 写进运行期 JSON（体积与噪声），放 data/provenance/。

## 6. 下游消费契约（给 src/core 的接口形状）

```ts
type PaletteSet = { id, label, brand, standard, beadSizeMm?, quality,
                    source, license, licenseNote?, codeStyle?, notes?, colors: PaletteColor[] }
type PaletteColor = { code, name?, nameEn?, hex: string|null, rgb?: [n,n,n],
                      kind: 'solid'|'special'|'transparent', family? }
// 加载时由 core/palette/loader 负责：校验 schema → 补 rgb → 过滤 kind!=='solid' 的
// 匹配色表 → 预计算 Lab 数组（含 code 索引映射）→ 生成 id->index 查找表。
```

### 7.2 采集步骤（Codex v1.1 子任务，复用 §4 流水线）
1. `fetch-sources.mjs` 增补：hank `beads.hex.txt`（MIT，Perler/Hama 段）与 beadmachine `colors_hama.json`（MIT）已有 provenance；如需官方转录，人工把色卡 hex 录成 `provenance/official-*.csv`（注明"人工转录自官方色卡图/PDF"）。
2. `normalize-to-palette.mjs` 新增两个 set 的生成规则（code 前缀 P/H、zeroPad=2、`kind` 标注 transparent/special 如 Perler 透明 P-Clear）。
3. `crosscheck.mjs`：官方转录 ↔ MIT 源重叠色号 ΔE 核对，差异表人工裁决。
4. `validate.mjs` + schema 绿；人工抽查白/黑/红/肤/蓝各 3 个常见色号观感。
5. `npm run build` 自动 `generate:palettes` 打包；UI 色板下拉出现两项，label 带 quality 徽标（官方转录=`official`；起步集=`community`，UI 注明）。
- 红线不变：不复制 pbdx/AGPL 链数据；MIT 源保留版权声明入 provenance；质量低于 `official` 的集在 UI 明确标注。
