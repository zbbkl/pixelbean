### 0.1 四个增强点与对应模块

### 0.2 兼容纪律（Codex 必须先读）

1. **不破坏既有 112 测试**：`speckleClean` / `shadowSimplify` / `clusterLimit`（v1 形态）**原样保留导出**，签名与行为一字不改（供旧用例与降级路径直接调用）。
2. `runPostPipeline` 内部改调 V2 各函数，并新增可选第 4 参 `protect`（`Uint8Array | null`，默认 null）。V2 在 `protect=null` 且默认参数下与 v1 在**典型输入**上结果一致；允许的语义修订方向见 0.3。
3. 数据契约：掩码**不进入 `Pattern`、不进入 worker 协议、不进入草稿/RLE**，仅在 `convertPipeline` 调用链（worker 内）传递；contain 板需同步搬移掩码（§6.4）。
4. golden：本版若需改 fixture，只允许在“杂色更少 / 暗层更少 / 主色保留更稳 / 特征保留”方向上变化，逐条记录原因（§8）。

### 0.3 允许的语义修订（相对 docs/03 §9 / v1.1 已落地实现）

| 修订 | 内容 | 理由 |
|---|---|---|
| S1 | 噪点清理：单格并入要求“同一边界色 ≥2 条邻边且占比 ≥50%”（v1.1 只要求“存在众数”）；2..N 格连通合并要求贴附边 ≥ 域格数 | 避免“四向被不同色包围的 1 格”被任意并入一色造成的新杂色（本版诉求） |

## 1. 管线总览与类型/签名增量

### 1.1 v1.2 管线（在 docs/03 §9.0 基础上插入特征阶段与掩码流）

```

  → [A] 背景合成（不变，§1）
```

## 2. 二阶孤立噪点清理 `speckleCleanV2`

### 2.1 术语与目标

- “**一阶**”＝单格删除：清除**四周明显贴着同一主体**的 1 格杂色。
- “**二阶**”＝小连通域合并：1 格并入后（或天然存在的）2..N 格同色连通域，若整体“像贴在某个主色块侧缘的赘生物”则整域并入该主色块。
- “**主色块**”＝小域边界上出现次数最多的那个**已用色板索引**，且贴附强度满足阈值（避免把“两种大色交界处的孤立格”武断并入某一侧）。
- 判据全部基于 `palette.labs` 的 **CIEDE2000**；并列取索引小者；**单向前进一遍**（Phase1 后重标一次再 Phase2），不迭代到收敛（与 v1.1 纪律一致）。

### 2.2 参数表（默认值 + 边界）

| 参数 | 语义 | 默认/取值 |
|---|---|---|
| `noiseMax` | 清理粒度：1=仅单格；2=单格+双格；3=再加三格连通串 | 沿用 UI 1..3，默认 2 |
| `deltaEthr` | 并入阈值（CIEDE2000） | 沿用 UI 20..40，默认 30 |
| `BOUND_SINGLE_MIN` | 单格并入：众数边界边数下限 | 2（4-邻域最多 4 边） |
| `BOUND_MAJOR_MIN(s)` | 连通域并入：众数边界边数下限 | `s`（域格数） |
| `BOUND_SHARE` | 众数边数 / 域总边界边数 下限 | 0.5 |
| `protect` | 掩码：含保护格的域一律跳过 | `null`（关） |

### 2.3 伪代码（可直接译 TS）

```
labelComponents(cells, W, H) → Component[]   // 复用 speckle.ts 现有实现（4-邻域、同色同域、boundary Map 忽略 -1/出界）

boundaryMajority(comp):
  // 返回 { color, count, total }；total=Σboundary；空 boundary → null
  top = (count 最大, 并列取 color 小) 的颜色;  total=Σ counts
  return { color: top.color, count: top.count, total }

speckleCleanV2(pattern, palette, noiseMax=2, deltaEthr=30, protect=null):
  cells = Int16Array(pattern.cells)
  // ---------- Phase 1：单格删除 ----------
  comps = labelComponents(cells)                    // 排序: (size asc, color asc)
  for comp in comps:
    if comp.size != 1: continue
    if protect != null && protect[comp.cells[0]] == 1: continue     // 特征格不删
    m = boundaryMajority(comp); if m == null: continue
    if m.color == comp.color: continue
    if m.count >= BOUND_SINGLE_MIN
       && m.count / m.total >= BOUND_SHARE
       && ΔE2000(palette[comp.color], palette[m.color]) <= deltaEthr:
         cells[comp.cells[0]] = m.color
  // ---------- Phase 2：2..N 格连通合并（“二阶”） ----------
  comps2 = labelComponents(cells)                   // 重标号，吸收 Phase1 结果
  for comp in comps2:
    s = comp.size
    if s < 2 || s > noiseMax: continue
    if 任意 cell ∈ comp 且 protect[cell]==1: continue
    m = boundaryMajority(comp); if m == null: continue
    if m.color == comp.color: continue
    if m.count >= BOUND_MAJOR_MIN(s)                // 贴附边 ≥ 域格数
       && m.count / m.total >= BOUND_SHARE
       && ΔE2000(palette[comp.color], palette[m.color]) <= deltaEthr:
         for cell in comp.cells: cells[cell] = m.color
  return { ...pattern, cells }
```

### 2.4 边界与例外（逐条写注释）

1. **四向被不同色包围的 1 格**：众数 count=1 <2 → 不并（保留；S1 的意图）。
2. **两个同色相邻格悬在主色块侧缘**（“2 格连通合并”主场景）：每格各有 ≤3 条外边；若两块都主要贴同一 c2，union 众数 count≥2=s 且占比≥0.5 → 并入 c2。
3. **与留空相邻**：boundary 忽略 -1；纯“浮岛”（四邻全空/出界）boundary 为空 → 不并，绝不向空格蔓延（含 contain 板的空行）。
4. **深色瞳孔/2 格特征**：ΔE(瞳孔,肤色) 通常 >30 → 不并；若 ≤30 但被 `protect=1` 覆盖（§4 产生的眼睛/细线/点缀格）→ 本函数无条件跳过该域。
5. **全图一色/无小域**：无边界 → 幂等原样返回。
6. **noiseMax=3**：三格“一字串”贴同一主体时 union 众数边≥3 可并；三格 L 形若贴附同样达标也可并——判据统一为 BOUND_MAJOR_MIN(s)=s 与占比，不按形状特判。
7. **确定性**：所有遍历按 (size,color)/(行优先) 排序；并列取索引小者。

### 2.5 与 v1.1 `speckleClean` 的关系

- `speckleClean(pattern,palette,noiseMax,deltaEthr)` 原样保留（导出+行为），供旧测试/旧调用。
- 在“边界存在明确主色”的典型输入上（既有 golden 均属此类），V2 与 v1 输出一致；仅 S1（多色包围不并）与 protect 分支有差异。

## 3. 暗部简化增强 `shadowSimplifyV2`

### 3.1 目标与分层策略

- 只收敛“**近中性暗部**”（深棕/深褐/灰黑：低明度且低彩度）——这是拼豆玩家眼里的“杂色冗余暗部”；
- **纯彩色暗部**（深红/深蓝/深绿等，高彩度）**不并入中性锚**，只允许**同色相族内**的小半径收敛（保留色相可读性）；
- 收敛结果用“**锚点数**”显式封顶：标准档近中性暗部存活 ≤2 层、强档 ≤1 层（把“暗部 1~2 层收敛规则”固化为可数指标）。

### 3.2 池与参数

```
近中性暗部池 A = { used c | L*(c) < 45 且 C*(c) ≤ 45 }        // C*=√(a*²+b*²)
有色暗部池   B = { used c | L*(c) < 45 且 C*(c) > 45 }
（阈值依据：MARD 深棕系 L*≈25–40、C*≈10–45；近黑 L*<20）
```

| 参数 | 语义 | 值 |
|---|---|---|
| `DARK_L` | 暗部明度上界 | 45（沿用） |
| `DARK_C_NEUTRAL` | 中性/有色暗部彩度分界 | 45 |
| `T_STD` | 标准档并入半径（ΔE2000） | 18（沿用 level1 阈值） |
| `T_STRONG` | 强档并入半径 | 28（沿用 level2 阈值） |
| `T_COLOR` | B 池同族小半径 | 14 |
| `COLOR_SURPLUS_RATIO` | B 池“余量色”判定：count < 族内最大用量×该比 | 0.20 |
| `K_ALLOW` | 近中性暗部允许存活层数：level1=2、level2=1 | 依档位 |

### 3.3 伪代码

```
shadowSimplifyV2(pattern, palette, level, protect=null):
  if level==0: return pattern
  used = 已用索引（升序）
  poolA = [c in used | L<45 && C<=45]; poolB = [c in used | L<45 && C>45]
  if poolA.isEmpty && poolB.isEmpty: return pattern          // 幂等
  cells = Int16Array(pattern.cells)

  // ---- 1) A 池：贪心锚点收敛（结果层 ≤ K_ALLOW 由构造保证）----
  sort poolA by (L asc, index asc)
  anchors = []                                               // 各锚 = 池内某已用索引
  targetFor: Map<color, anchorColor>
  for c in poolA:
    best = argmin_{a in anchors} ΔE2000(palette[c], palette[a])   // 并列取先入锚
    if best != null && ΔE(best) <= (level==1 ? T_STD : T_STRONG):
        targetFor[c]=best
    else if anchors.length < K_ALLOW:
        anchors.push(c)                                      // c 升格为锚
    else:
        targetFor[c] = best                                  // 超半径也并入最近锚（保证 ≤K_ALLOW）
  // ---- 2) B 池：同色相族内小半径收敛（保色相）----
  // hue 族判定复用 clusterLimit 的 familyOf 口径（C*>45、hue 差≤20°、族跨度≤60°）
  famOfB = hueFamily(poolB)
  for fam in famOfB:
    main = fam 内 usage 最大（并列 index 小）
    for c in fam \ {main}:
      if usage(c) < usage(main)*COLOR_SURPLUS_RATIO && ΔE2000(c, main) <= T_COLOR:
         targetFor[c] = main
  // ---- 3) 掩码约束（§4 特征格）----
  //    对 protect 格所在色 c：仅允许“池内收敛”（A→A / B→同族 B），禁止 B→A 跨池；
  //    A 池特征色（如瞳孔黑）若与锚 ΔE 过大（>T 档半径）则保持原色不并入。
  if protect != null:
    for cell i where protect[i]==1 && cells[i]>=0:
      c = cells[i]
      if c in targetFor && 目标池允许(见上)：保持 targetFor[c] 生效
      else: targetFor.delete(c)                             // 撤销该色的并入
  // ---- 4) 重映射 ----
  changed=false
  for i: if cells[i]>=0 && targetFor.has(cells[i]): cells[i]=targetFor.get(cells[i]); changed=true
  return changed ? {…pattern, cells} : pattern
```

### 3.4 边界与例外

1. 全图无 L*<45 已用色 → 原样返回（浅色图幂等，沿用 v1.1 行为）。
2. **彩色暗部不误并**：深红 C*≈55 >45 → 在 B 池，只可能并入**同 hue 族**的深红（ΔE≤14 且用量余量色）——与 docs/01 v1.1 DoD B“纯彩色暗部（深红等）不被误并”兼容。
3. **深蓝+深棕并存**：分属不同 hue 族的 B/A → 各自保留，色相不互染。
4. 强档的“压到 1 层”：对 A 池内 ΔE>28 的极端远色（如近黑 vs 深棕）也并入最近锚 —— 这是强档语义（层数保证优先），与 v1.1 的“28 半径内才并”不同（S2），在 UI 说明文字里写“强：暗部统一为一层”。
5. 掩码撤销逻辑只撤销“该色在 map 中的并入”，**不影响其它色**；同色多个格共享同一 targetFor 判定，撤销是整色级的（特征色通常是 2..4 格小簇，色级撤销可接受且实现简单）。

### 3.5 验收指标

- level1：收敛后 A 池存活层 ≤2（构造保证）；level2：≤1。
- B 池：合并只发生在同 hue 族，任意两结果色若 C*>45 且 hue 差 >20° 必不同族（无跨族染污）。
- **计数口径**：A 池层数统计**排除 protect 掩码格所在色**——被刻意保留的特征暗色（如瞳孔近黑）不算违反收敛指标（§3.3 掩码步）。

## 4. 小特征保护（降采样阶段）`features.ts`

### 4.1 目标与适用

在**降采样阶段**识别并保留三类高对比小面积特征，使它们不会在“面积平均”下被洗成周围色：

1. **细线条**（1 格宽的眉/眼线/描边穿过若干格）：跨格连续性；
2. **点状高光/点缀**（眼睛高光点、彩色小点）：全局成簇证据；
3. 整格级成片特征（≥2×2 眼睛、腮红块）：该格多数像素即特征色，`average` 本身会保留其颜色；其“形状不被当噪点/不被限色抹掉”由两条既有+新增机制保证——speckle 只动 ≤noiseMax 格小域（成片 >2 格天然不删），`clusterLimitV2` 的暗/亮/饱和/主色保护覆盖常见点缀色（如深瞳=最暗、粉腮红常为最饱和）。**本模块只负责改写“单格内特征占少数”的格子**（细线、小点、跨格过渡），输出改写色 + 保护掩码。

输出两件事：改写后的 `cells`（个别格取特征色）与 `protect` 掩码（供 H1/H2/H3 消费）。**与模式正交**：average 与 dominant 都可用；预设见 §6.3。

### 4.2 单元分类器（每格，纯局部）

对格 (gx,gy) 的源像素区域（与 `downsampleAverage` 相同区间公式）做一次扫描：

```
classifyCell(regionPixels): 
  n = 像素数; if n < FEATURE_REGION_MIN_PX(8): return null
  // 亮度两分类：线性 Y（用 srgbByteToLinear 预计算的 0..1 值；沿用 §3.1 同一函数）
  Ylo = min Y, Yhi = max Y; if Yhi - Ylo < FEATURE_CONTRAST_MIN(0.10): return null
  t = (Ylo+Yhi)/2
  repeat 2:                                       // 确定性迭代
     A = {p | Y<=t}, B = 其余
     t = (meanY(A)+meanY(B))/2                    // 若任一侧为空 → 提前返回 null
  令 F = count 小侧（特征侧），M = count 大侧（主体侧）；两者 mean 线性 RGB → meanSrgb(F/M)
  ΔY = |meanY(F)-meanY(M)|; if ΔY < FEATURE_CONTRAST_MIN: return null
  share = |F|/n                                   // ≤0.5 恒成立（F 定义）
  if share < FEATURE_SHARE_MIN(0.02) || share > FEATURE_SHARE_MAX(0.5): return null
  bbox: bw = maxX-minX+1, bh = maxY-minY+1（region 局部坐标）
  fracW = bw/regionW; fracH = bh/regionH
  if fracW<=FRAC(0.35) && fracH<=FRAC: kind='dot'
  elif fracW<=FRAC && fracH>FRAC:     kind='vline'   // 竖向细条（竖贯或跨竖边）
  elif fracW>FRAC && fracH<=FRAC:     kind='hline'
  else: return null                                 // 占格主导 → 无需特征处理
  return { kind, meanSrgbF, meanSrgbM, ΔY }
```

### 4.3 网格仲裁（跨格，确定性）

```
downsampleWithFeatures(image, W, H, mode, bg, adjust):
  baseCells = downsample(image, W, H, mode, bg, adjust)      // 复用现有采样
  protect = Uint8Array(W*H)
  cand = [W*H] each: classifyCell(...) 或 null
  for g in 0..W*H-1 where cand[g]!=null:
     k = cand[g].kind
     if k == vline || k == hline:
        // 向线方向找邻格延续：vline→上下两格，hline→左右两格（越界/空格跳过）
        for each 邻格 nb in 该方向:
           if cand[nb]==null:
              ok = ΔE2000(srgbToLab(baseCells[nb*4..nb*4+2]), srgbToLab(cand[g].meanSrgbF)) <= FEATURE_LINE_DE(12)
           else:
              ok = ΔE2000(srgbToLab(cand[nb].meanSrgbF), srgbToLab(cand[g].meanSrgbF)) <= FEATURE_LINE_DE(12)
           if ok: 续上 → 写入 baseCells[g*4..g*4+2]=meanSrgbF(RGB 字节)、alpha=255; protect[g]=1; break
        // 未续上 → 不写（该格保留 base，避免 1 格噪点）
     if k == dot:
        // dot 候选先按 ΔY 过滤：ΔY < FEATURE_DOT_CONTRAST_MIN(0.35) 的 dot 不升格（弱对比点更像噪点）
        // 全局成簇：dot 格按 meanSrgbF 链式聚类（ΔE<=FEATURE_DOT_DE=12；顺序按 g 索引，
        // 每簇锚=簇内最小索引格；遍历其余 dot 格找 ΔE 最近已入簇者并入）
        // 簇有效条件：簇格数 >= FEATURE_DOT_MIN_TOTAL(4)
        //   （避免把一整片模糊渐变里的次级分区当特征）
        // 有效簇内所有格：写入特征色(baseCells[g*4..]+alpha=255); protect=1
        // 无效簇：不写（交给 H1 speckle 按噪点处理）
  return { cells: baseCells, protect }
```

### 4.4 常量总表（集中放 features.ts 顶部并注释依据）

| 常量 | 值 | 依据 |
|---|---|---|
| `FEATURE_REGION_MIN_PX` | 8 | 太少像素无统计意义 |
| `FEATURE_CONTRAST_MIN` | 0.10（线性 Y 差） | 低于人眼强对比（深瞳 vs 肤色 Y 差≈0.3+） |
| `FEATURE_SHARE_MIN/MAX` | 0.02 / 0.5 | 过低=噪声概率高；>0.5 会被并到 count 小侧定义排除 |
| `FEATURE_SHAPE_FRAC` | 0.35 | 区域某维 ≤35% 视作“条带” |
| `FEATURE_LINE_DE` | 12（ΔE2000） | 线色延续容差（颜色略有抖动仍续上） |
| `FEATURE_DOT_DE` | 12 | 点缀点成簇容差 |
| `FEATURE_DOT_MIN_TOTAL` | 4 | 全图同色点状特征最少格数（低于此更像噪点） |
| `FEATURE_DOT_CONTRAST_MIN` | 0.35 | 高对比点才算“特征点” |

### 4.5 掩码语义与消费点（贯穿后处理）

- `protect[g]=1` ⇔ “该格是刻意保留的特征格”，**H1 不并、H2 只允许池内收敛（§3.3 掩码步）、H3 所在色进保护集（§5.4）**。
- 掩码是**形状层**语义：特征的“形状/位置”不消失；颜色可被 H2（暗→暗）或 H3 收敛到更少层，但绝不被并入“皮肤/背景”等语义异色。
- **颜色身份的分层保证**：掩码只管形状；特征色（尤其成片点缀）是否在 H3 存活还依赖 `clusterLimitV2` 的暗/亮/饱和/主色保护与 Step0b“跳过保护集”规则（docs/19 §5.4）——验收按 §4.1-3 的分工设计，不要求掩码承担全部保色责任。

### 4.6 边界与说明

1. 空格（-1）没有 protect 概念：掩码只在内容格产生（features 在 placeContain 之前按内容网格生成，§6.4 搬移）。
2. **与抖动同开**：抖动路径在 match 前对 `baseCells` 逐格量化，不消费掩码（掩码只在 match 后管线生效）；UI 说明“开启抖动时细节保护降级为参与抖动”。
3. **与 dominant 同开**：多数实色区格内无“双类”分布 → classify 返回 null，行为等价 dominant 原样；仅高对比双类区可能改写，无害。
4. **特征格总量上限**（防滥用）：仲裁写入时维护 `writtenCount`，当 `writtenCount ≥ PROTECT_CAP`（= max(24, round(W*H*0.02))）后**不再写入**任何新特征格（保留该格 base，继续扫描）——按 g 索引升序天然“先到先得”，无需回退副本，确定性裁剪。保证特征格不会反过来“保护一片噪点”。
5. 合成/纯色图（单类区域）→ 无候选 → 幂等，golden 不回归。

## 5. 主色优先的智能限色 `clusterLimitV2`

### 5.1 相对 v1.1 的升级点

1. **近似重复色预合并**：ΔE2000≤2 的“双胞胎色号”先并为用量大者（同 hue 自动合并的极端情形；跨族不适用，因为 ΔE≤2 必近同色）。
2. **边缘小份额色预归并**：用量 ≤ MARGINAL_CELLS 且与最近已用色 ΔE≤24 的色先并入最近色（不占配额）。
3. **主色保护**：用量占比 ≥5% 的“主色”进入保护集（用量序取前 floor(K/2)，防保护集过大反噬配额）。
4. **族内代表“主色必保”**：代表集 = {族内用量最大色} ∪ 明度极值补位，替换 v1.1 的“明度等距取代表”（后者会把中段主色挤出）。

### 5.2 参数表

| 参数 | 值 | 说明 |
|---|---|---|
| `DUPE_DE` | 2.0 | 近似重复色并入阈值 |
| `MARGINAL_SHARE` | 0.002 | 边缘色 = 用量 < round(占用×0.002) |
| `MARGINAL_DE` | 24 | 边缘色并入阈值 |
| `MAIN_SHARE` | 0.05 | 主色 = 用量占比 ≥5% |
| `MAIN_GUARANTEE_MAX` | `max(1, floor(K/2))` | 保护集里主色数量上限 |
| `MAX_FAMILY_LAYERS` | 3 | 沿用（族内 ≤3 层） |
| hue 族参数 | `GRAY_CHROMA=8 / HUE_GAP=20 / MAX_FAMILY_SPAN=60` | 沿用 clusterLimit 现有实现口径 |

### 5.3 伪代码

```
clusterLimitV2(pattern, palette, K, protect=true, protectMask=null):
  counts = 各色用量（cells≥0 统计）
  if counts.size <= K: return pattern
  // ---------- Step 0：预合并（确定、可撤回到 remap） ----------
  used = counts 排序 (count desc, index asc)
  # 0a 去重：对 used 中每色 c，找最近其他已用色 d（ΔE2000 最小，并列 index 小）；
  #    若 ΔE(c,d)<=DUPE_DE 且 usage(d)>=usage(c)（并列 index 小者保留）→ 记 remap0[c]=d
  # 0b 边缘色：对未在 0a 中被并入的 c：usage(c) <= MARGINAL_CELLS(=round(占用*MARGINAL_SHARE), 至少2)
  #    且 ΔE 最近已用色 <= MARGINAL_DE → 记 remap0[c]=nearest
  #    保护条件：0a/0b 都跳过 protectMask 标记格所在色（一旦是特征色不预并）
  #    预并立即作用于 counts（被并色 count 加到目标色），后续用“合并后”用量
  // ---------- Step 1：hue 族（复用 familyOf 现有实现） ----------
  groups = familyOf(合并后 used)
  // ---------- Step 2：保护集 ----------
  protectedSet = 最暗∪最亮∪最饱和（现有 protectedIndices 口径）
  if protectMask: protectedSet ∪= { c | 存在 protectMask[i]==1 && cells[i]==c }
  mains = 按用量 desc 取 used，占比>=MAIN_SHARE 者取前 MAIN_GUARANTEE_MAX 个
  protectedSet ∪= mains
  // ---------- Step 3：族配额 + 主色必保代表 ----------
  total = Σ counts
  for fam in groups:
    famUsage = Σ counts; q = max(1, round(famUsage/total * K))
    limit = min(q, MAX_FAMILY_LAYERS, |fam|)
    if limit == |fam|: final ∪= fam; continue
    mainIdx = fam 内 usage 最大（并列 index 小）
    if limit == 1: reps = [mainIdx]
    else:
      byL = fam 按 (L asc, index asc)
      lo=byL[0]; hi=byL[last]
      reps = [mainIdx]
      extra = limit-1
      if mainIdx==lo: reps+=[hi]
      elif mainIdx==hi: reps+=[lo]
      else: // 主色居中：先补更远极值（|L(hi)-L(main)| 与 |L(main)-L(lo)| 大者；相等取亮侧）
            reps += 较远极值; 若 extra==2 → 再补另一极值
      // extra==2 且 mainIdx 已是极值情形：补另一极值后再按 usage desc 补位到 limit
      while |reps| < limit: reps += 未入选中 usage 最大者（并列 index 小）
    final ∪= reps
  for idx in protectedSet: final.add(idx)
  // ---------- Step 4：族内层数裁剪（保护色除外）+ 全局 K 裁剪（沿用现有 removeUntilLimit 思路） ----------
  final = keepFamilyLayerLimit(final, groups, protectedSet, palette)   // 现有逻辑：仅删非保护
  // protectedOrder 删除顺序 = [saturated, bright, dark]（现有语义，最先生效删）后接 mains（按用量升序，
  // 用量小的主色先删，主用量最大的主色最后删）——保证“主色”只在 K 实在不足时按最弱→最强顺序牺牲。
  final = removeUntilLimit(final, protectedSet, protectedOrderWithMainsLast, K, palette)
  // ---------- Step 5：重映射（现有 nearestInSet 逻辑） ----------
  for i in cells: cells[i] = cells[i]<0 || final.has(cells[i]) ? cells[i] : nearestInSet(lab(cells[i]), final)
  return { …pattern, cells, options: { …options, maxColors: K } }
```

### 5.4 保护边界

1. **主色不因层压缩消失**：代表选法保证族内用量最大者恒在 final（除非 K 小于保护集规模的极端情况由 removeUntilLimit 兜底按既有顺序舍弃：饱和→亮→暗）。
2. **特征色入保护**：protectMask 格所在色不会被预并（Step0）也不会被族内裁剪（Step4），保证“眼睛/细线色”即使占比极小也不被洗成肤色。
3. **不新增色号**：全部 remap 目标 ∈ 合并后 used ⊆ 原 used（K+1 例外仅 outline）。
4. **同 hue 自动合并总述**：ΔE≤2 直接并（0a）；族内非代表成员在 Step3 天然并入最近代表（v1.1 同款“并入保留集内最近者”）。

### 5.5 验收指标

- 输出色数 ≤K；统计/CSV/导出结构不变。
- 黄色系合成图：同族 ≤3 层（沿用 T13）；**主黄（用量最大成员）恒在输出中且其用量仍为该族最大**。
- 卡通样例 ≤24 色；暗部层经 H2 后单层（沿用 T13/T14 语义）。

### 6.4 contain（方形板）掩码搬移

```ts
// features.ts 导出纯函数（可单测）：
export function placeProtectMask(mask: Uint8Array | null,
  contentW: number, contentH: number, boardW: number, boardH: number): Uint8Array | null {
  if (!mask) return null;
  const out = new Uint8Array(boardW * boardH);
  const ox = Math.max(0, Math.floor((boardW - contentW) / 2));
  const oy = Math.max(0, Math.floor((boardH - contentH) / 2));   // 与 placeContain 同式
  for (let y = 0; y < contentH; y += 1)
    for (let x = 0; x < contentW; x += 1)
      out[(oy + y) * boardW + ox + x] = mask[y * contentW + x];
  return out;
}
```

> 必须与 `placeContain` 保持同一偏移量（同文件同式），否则留空行上出现保护格。

## 7. 下游开发 FAQ（技术疑问答疑与方案调整依据）

**Q1 为什么不把保护掩码塞进 `Pattern`？**
`Pattern` 承担三条对外链路：worker 协议（cells 以 `Int16Array` transfer 回主线程）、草稿/RLE 序列化（`encodeCellsRle`）、统计/CSV/导出。掩码是**转换中间产物**，只有后处理（H1–H3）消费；放进 Pattern 会强迫协议/序列化/统计全链路感知它，突破“数据结构规范一致”边界。因此掩码只存在于 worker 内 `convertPipeline` 局部变量，随调用链传递。

**Q2 会不会新增“无效色号”？**
不会。§2/§3/§5 的一切目标色 ∈“已用色板索引”∪（Step0 预并目标=已用色）；特征的 F 色是源图像素色而非色板色，它只参与“该格选哪个源代表色”，最终仍经 §E 匹配到色板索引。全链唯一可能“+1 色号”的仍是 outline（docs/03 §9.4，UI 明示 K+1）。

**Q3 掩码长度与 Pattern 尺寸不一致怎么办？**
规格保证：掩码在内容网格（`contentW×contentH`）生成；contain 扩板时用 `placeProtectMask` 同步搬移；非 contain 时掩码长度==网格长度。V2 各函数对 `protect` 逐格取 `protect[i]`，若调用方传错长度属实现错误——单测覆盖（§8 T26）。

**Q4 性能预算？**
features 每格区域做一次亮度两分类（像素一次线性 Y 预计算，A/B 两遍累加），总扫描 ≈2× 源像素；限色/噪点/暗部均为 O(格数)。以 MAX_CELLS=150k、源 ≤16M 像素为上限，worker 内单次耗时与现有 downsample 同数量级（自测记录，不做硬超时断言以免 CI 抖动）。

**Q5 确定性怎么保证？**
无随机；所有 argmax/排序并列取“索引小者优先”（§2 按 size/color、§3 按 L/索引、§4 按 g 索引链式、§5 按 count/索引）。两分类迭代 2 轮、阈值取均值，均为输入到输出的纯函数。golden 回归用整段 hash 不变。

**Q6 特征格上限 `PROTECT_CAP` 为什么存在？**
防止“一条 200 格长的斜向细线”或大面积抖动边缘把掩码灌满、让 H1/H3 失去意义。上限=max(24, 2%·格数)，超限按索引序裁剪——语义上保护“最能说明问题”的起始特征段，避免把后处理彻底架空。

**Q7 speckle V2 判据比 v1.1 严格（S1），会不会让旧的“1 格噪点全清”类测试失败？**
典型 golden（黄色渐变/卡通样例）的孤点都被 ≥2 边同主色包围，V2 判据照常触发，输出不变；只有“四向四色包围的 1 格”（本应保留的边界信息）不再被乱并。若个别 fixture 因此变化，按 §8 记录并更新（方向：杂色更少/更合理）。

**Q8 与 docs/01 的既有 DoD（T13–T20）关系？**
v1.2 增强不推翻 v1.1 DoD：T13（≤24 色、黄色 ≤3 层）、T14（暗部单层/彩色暗部不误并）、T15（成片眼睛腮红保留）、T16（描边 1px）、T18（限色+抖动互斥）、T20（116 无半格）仍为验收基线；v1.2 在其上追加 §8 用例。

**Q9 为什么特征识别放降采样而不是 match 之后？**
特征判定的依据是“源图像素里的局部对比与形态”，此时图像还没被映射到离散色板；色板映射后（如腮红粉 vs 肤色）两者 ΔE 可能很小，无法再区分“刻意点缀”与“噪点”。放降采样阶段才能拿到“高对比但小面积”的第一手证据（呼应 S1 的噪点判据只对真杂色生效）。
