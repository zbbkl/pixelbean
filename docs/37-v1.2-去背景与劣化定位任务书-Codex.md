# 37 · 白底软阴影主体「去背景 + 质量劣化定位」任务书（Codex）

> 流程：DeepSeek Harness（规格）→ **Codex（实现）** → Claude Code（复核）。
> 关联：[`docs/34`](34-v1.2-终版商用优化算法设计文档.md)（柔边/小特征家族方案，未在本任务实施）；[`docs/35`](35-v1.2-P0-1修复任务书-Codex.md)（P0-1 已修复，与本任务无关）；[`docs/36`](36-v1.2-P0-1修复自测报告.md)。
> 背景素材审核：**源图** = 白底 3D 软阴影小白兔（奶龙类：白身、浅米腹部、粉耳尖、青绿眼、整体柔和明暗 + 脚下灰接触阴影）；**当前输出**（78×78 方形底板）= 整体发灰、主体下方一团灰影、边缘灰噪、头/耳近白区与白底混淆出现「缺块」。

---

## 0. 一句话结论

当前输出劣化的**直接原因不是最近 P0-1 修复**（P0-1 只是把 E1 空桶平滑的亮度轴邻居权重从 0 修正为 0.5，几不变渐变带纹），而是 **v1.2 终版管线对「白底 + 软阴影 + 近白主体」照片的固有盲区**：管线把**白底当真实内容**、把**灰色软阴影当主体并吃掉**、且**方形底板 contain 用整图而非主体**。因此最小、确定性、风险最低的修复 = **像素化前的一键去背景 + 主体盒 contain**。

## 1. 问题定位报告（逐环节）

| # | 环节 | 文件 | 现象/机理 |
|---|---|---|---|
| 1 | 降采样 | `pipeline/downsample.ts` `downsampleDominantV2` | 对白底给出「白主导色」→ **白底被当真内容**；对脚下灰接触阴影（低对比灰渐变）选出「灰主导色」→ **主体下方灰影 blob**。 |
| 2 | 颜色量化 | `pipeline/match.ts` `matchGridDetailed` | 把白/米/灰阴影量化到若干近灰珠 → **整体发灰、发雾、变淡**。 |
| 3 | 特征保护 | `pipeline/features.ts` `classifyRegion`/`soft` | 「白身 vs 白底」低对比，`deltaY` 接近阈值、soft/boundary 分支（`meanF`/`meanM` 硬选一）难以判定；**头/耳近白区被当背景/被吞 → 缺块**。 |
| 4 | 合并/后处理 | `post/merge.ts`、`post/speckle.ts`、`post/clusterLimitV2.ts` | 近白头部小块易被并入邻近白底/白身（ΔE 小）→ **头部「缺块」**；灰影噪声被聚成杂色。 |
| 5 | 几何 contain | `pipeline/geometry.ts` `deriveContainContent` + `contain.ts` `placeContain` | **用整图尺寸**（含白底+阴影）等比缩放进方板 → 主体偏小、四周留空；内容盒含白底，加剧头部示意错位。**（已核：`deriveContainContent` 用 `scale=min(boardW/srcW, boardH/srcH)` 保证 `contentW≤boardW, contentH≤boardH`，`placeContain` 只在超板时 break 裁剪，故**不是几何裁剪导致缺块**，缺块来自采样/合并对近白头部的误并。）** |

**「缺块」根因（重点）**：头/耳为**近白**，与白底色差极小；降采样主导色+合并把这一小块并进白底/白身 → 视觉上一块缺失。**修复方向不是调整采样阈值，而是先抠出主体**，让白色头部明确落在主体 mask 内，不被白底混淆。

|---|---|---|---|

## 3. 最小修复方案（不引入更多不确定算法）

**核心 = 像素化前的一键去背景 + 主体盒 contain。** 单点、确定性、纯函数、可关、默认开。

### 3.1 新预处理模块 `src/core/pipeline/subject.ts`

```ts
export interface SubjectResult {
  cells: Uint8ClampedArray;   // 背景 alpha=0，主体保留原色
  mask: Uint8Array;           // 1=主体，0=背景（已抠出）
  bbox: { x0: number; y0: number; x1: number; y1: number } | null;
}

export function extractSubject(
  source: CellImage,
  opts: { tol?: number; edge?: number; minArea?: number; holeMax?: number } = {}
): SubjectResult
```

**算法（确定性，无随机，无 ML）**：

```text
1) 背景色估计 bgColor：
   取四边所有像素的 Lab 中位数（Lab 用 srgbRgbToLab）。

2) 边界洪水填充（从四边像素出发）：
   mask[..] = 0
   queue = 四边像素中 ΔE(px, bgColor) <= tol 者，全部入队并 mask=1
   while queue:
       p = pop
       for n in 4邻:
           if mask[n]: continue
           // 本地梯度 = 该像素与它 4 邻的最大 ΔE
           g = max_{nn∈4邻(n)} ΔE(px[n], px[nn])
           if ΔE(px[n], bgColor) <= tol AND g <= edge:
               mask[n] = 1; push n
   // edge-stop 是关键：主体轮廓（软阴影/边缘/描边）处梯度大 → 洪水在轮廓处停下，
   // 因此「白色头部」虽与白底同色，但被轮廓梯度屏障挡在主体内，不会被吞。

3) mask 后处理（小，确定性）：
   - 去除背景孤岛（< minArea px 的 mask=1 连通域 ⇒ 置 0）。
   - 填充主体内小洞（< holeMax px 的 mask=0 闭合洞 ⇒ 置 1）。

4) 输出：
   cells：mask=0 处 alpha=0；mask=1 处保留原 RGBA。
   bbox：非背景像素的最小/最大包围盒（× 用于 contain）。
```

**阈值建议**：`tol=10`（ΔE）、`edge=14`（本地梯度上限）、`minArea=0.5% 像素`、`holeMax=16px`。可集中导出便于 A/B 与回归。

### 3.2 管线接入（不改对外数据契约）

- `ConvertOptions` 增加可选 `removeBackground?: boolean`；`UiSettings` 增加 `removeBackground: boolean`（见 §4）。
- 在 `convertPipeline` **最前**（在 downsample 之前）：若 `removeBackground`，则 `const sub = extractSubject(source)`，用 `sub.cells` 作为后续采样的 `source`；并把 `sub.mask` 降采样到输出网格得到 `subjectMask`；`sub.bbox` 供正方形底板 contain 使用。
- 匹配产出 `pattern` 后：**凡 `subjectMask[cell]=0` 的格置为 `-1`（空格）**，并把这些格**排除**出 `distinctColorCount / clusterLimitV2 / merge / 统计 / 用料`（即当作空位，不出色号）。
- 方形底板 contain：`removeBackground` 时，用 `sub.bbox` 映射到输出网格得到内容盒；否则维持现状（整图）。
- 关闭 `removeBackground` 时行为**与现在完全一致**（兼容旧）。

> 说明：`mask=1` 与 `protect` 是两回事并可并存——`protect` 用于「主体内要保的小特征」，`mask` 用于「是否为主体的空间判定」；后端在 `mask=0` 处直接置空格，无需 `bg` 合成。

### 3.3 为什么这是「最小且不引入更多不确定性」

- 只新增一个确定性的空间域模块 + 一处「置空格」逻辑 + 一处 contain 内容盒替换。
- 不改变 CIEDE2000 匹配、不改变限色/合并/描边主体算法；关闭开关即回退。
- 直接消除白底（P0-A）与灰影 blob（P0-B 的主体最大化与头部缺块）。

## 7. 风险与说明（诚实边界）

- **近白头部 vs 白底**：若主体某处与背景色完全一致且**无任何轮廓梯度**（纯白无缝贴合），洪水可能渗漏；此时可上调 `tol`/收紧 `edge` 或加「主体须为最大连通域」兜底。属残余风险，需用真实样例校准阈值。
- **未运行真实 jpg 于 harness**：`.tools/bench/` 无 JPEG 解码器，本任务未逐像素跑样例；上方定位基于**两张提供给 DeepSeek 的截图 + 对 `contain.ts/geometry.ts/image.ts/downsample.ts/match.ts` 的逐行核验**，机理与截图现象一致。Codex/Claude 请在可运行环境用真实样例（docs/38）最终复核。
- **P0-1 无关**：本劣化为「无去背景」对白底软阴影照片的固有结果，与最近 P0-1 修复无因果（已在 §0 说明）。
