# 03 · 算法设计与伪代码

> 目的：让 Codex **无歧义**地实现核心算法；伪代码可直接翻译为 TypeScript。
> 决策依据见 `docs/00`（三家旗舰均弃 RGB 欧氏、默认无抖动等）。
> 所有核心函数放在 `src/core/`，零 DOM 依赖、确定性（禁随机）、可单测。

## 0. 转换管线总览

```
输入图片(ImageBitmap/HTMLImageElement)
  → [A] 背景合成（透明像素垫白/垫黑，见 §1）
  → [B] 预处理滑杆（亮度/对比度/饱和度，P1，默认恒等）
  → [C] 网格化 + 降采样：长边 N 格（锁宽高比）→ W×H 个格子 → 每格一个"代表色"
       模式：面积平均(默认) | 主导色            (§2)
  → [D] 加载色表 → 每色预计算 Lab（缓存）       (§3)
  → [E] 逐格最近邻匹配（CIEDE2000）→ Pattern    (§3)
  → [F] 可选 限色（≤N 色 + 关键色保护）          (§4)
  → [G] 可选 抖动（Floyd–Steinberg，默认关）     (§5)
  → 统计 + 渲染 + 导出
```

顺序说明：限色(F)作用于匹配结果之上（重映射）；抖动(G)与限色互斥或"限色后再抖动"，v1 规定：**勾选限色时抖动选项置灰禁用**（避免组合爆炸，P1 再放开）。

## 1. 背景合成与 alpha 处理

规则（v1）：
- `alpha == 0` 的像素 → 直接用背景色。
- `0 < alpha < 128` → 视为半透明，与背景色在 **sRGB 空间** 按 alpha 混合（简单起见不做预乘线性混合）。
- `alpha >= 128` → 忽略 alpha，用像素自身颜色。
- 背景选项：白色(默认) / 黑色 / 棋盘格仅用于 UI 展示预览，不参与转换。

```
function compositeOverBg(r,g,b,a, bgRgb):
  if a <= 0:        return bgRgb
  if a >= 128:      return (r,g,b)
  t = a/255
  return (round(r*t + bgR*r*(1-t))? …)  // 标准 over 合成：c = c_fg*t + c_bg*(1-t)
```

## 2. 网格化与降采样

### 2.0 尺寸推导（锁宽高比，绝不拉伸）

```
// 输入：原图宽 sw、高 sh；用户语义 = "长边 N 格"
if sw >= sh:  W = N;  H = max(1, round(sh * N / sw))
else:         H = N;  W = max(1, round(sw * N / sh))
```

预设按钮（29×29 等方形）等价于"短边=29"？不 —— 按 §规格：预设是**成品常用尺寸**，语义仍为方形（W=H=29）时如果原图非方形 → 行为 = **contain**（居中放，两侧空出）还是 cover（裁切）？规定 v1：预设方形尺寸时用 **contain + 空行**(cells=-1 空)，等同真实底板留空；任意格数模式用"长边=N"。两种语义都要在 UI 写明。

### 2.1 面积平均（保留可选；v1.2-final 起默认主导色改见 §0.3）

对格子 (gx, gy)，取源图像素覆盖区间：
```
x0 = floor(gx * sw / W), x1 = max(x0+1, floor((gx+1) * sw / W))   // 含端点
y0 = floor(gy * sh / H), y1 = max(y0+1, floor((gy+1) * sh / H))
```
逐像素：先按 §1 得有效 (r,g,b)，**γ 解码转线性**（§3.1），加权累加；未覆盖像素计 0。
最后线性均值 → γ 编码回 sRGB 8bit，作为该格代表色。

```
function downsampleAverage(img: Rgba[], sw, sh, W, H, bg): CellColor[W*H]
  for gy, gx:
    linSum = [0,0,0]; n = 0
    for y in [y0,y1): for x in [x0,x1):
      (r,g,b) = compositeOverBg(img[y*sw+x], bg)
      (lr,lg,lb) = srgbToLinear(r,g,b)
      linSum += (lr,lg,lb); n++
    (lr,lg,lb) = linSum / n
    cell[gy*W+gx] = linearToSrgb(lr,lg,lb)
```

### 2.2 主导色（适合本来近似的图/线稿/表情包）

对每格：内部像素转线性后，每通道按 **6bit（64 级）** 量化成桶号 → 统计直方图 → 取**众数桶** → 该桶内像素求**线性均值**作为代表色；桶数相同按桶号小者优先（确定性）。

```
bucket = (round(linear*63))   // 0..63
hist[bucketX*4096 + bucketY*64 + bucketZ]++
maxBucket = argmax(hist)（并列取最小桶号）
代表色 = 落入 maxBucket 的像素之线性均值 → γ 编码回 sRGB
```

## 3. 颜色匹配：sRGB → Lab(D65) + CIEDE2000

### 3.1 sRGB ↔ 线性（IEC 61966-2-1 精确分段）

```
srgbToLinear(v8):  c = v8/255
  return c <= 0.04045 ? c/12.92 : ((c+0.055)/1.055)^2.4
linearToSrgb(cl):  clamp(cl,0,1); c = ...（反函数，逐段）
  return round( (c <= 0.0031308 ? c*12.92 : 1.055*c^(1/2.4) - 0.055) * 255 )
```

### 3.2 线性 → XYZ → Lab（D65，白点 Xn=95.047, Yn=100, Zn=108.883，Y 用 0–100 标度）

```
linearToXyz(lr,lg,lb):   // 0..1 线性 → XYZ(0..~100)
  X = 0.4124564*lr + 0.3575761*lg + 0.1804375*lb
  Y = 0.2126729*lr + 0.7151522*lg + 0.0721750*lb
  Z = 0.0193339*lr + 0.1191920*lg + 0.9503041*lb

xyzToLab(X,Y,Z):
  f(t) = t > 216/24389 ? t^(1/3) : (24389/27 * t + 16)/116
  L = 116*f(Y/Yn) - 16
  a = 500*(f(X/Xn) - f(Y/Yn))
  b = 200*(f(Y/Yn) - f(Z/Zn))
```

**工程要点**：`linearToLab = xyzToLab ∘ linearToXyz ∘ srgbToLinear`。色表在**加载时**把每色转成 Lab 存数组（只算一次）；像素侧逐格转换。ΔE2000 计算见下（Sharma 2005 完整式，kL=kC=kH=1）。

```
function ciede2000(L1,a1,b1, L2,a2,b2):
  C1 = hypot(a1,b1); C2 = hypot(a2,b2)
  Cbar = (C1+C2)/2
  G = 0.5 * (1 - sqrt(Cbar^7 / (Cbar^7 + 25^7)))
  a1p = (1+G)*a1; a2p = (1+G)*a2
  C1p = hypot(a1p,b1); C2p = hypot(a2p,b2)
  h1p = C1p==0 ? 0 : (atan2(b1,a1p) in deg + 360) % 360
  h2p = C2p==0 ? 0 : (atan2(b2,a2p) in deg + 360) % 360
  dLp = L2 - L1
  dCp = C2p - C1p
  // Δh'（度）
  if C1p*C2p == 0: dhp = 0
  else:
    dhp = h2p - h1p
    if dhp >  180: dhp -= 360
    if dhp < -180: dhp += 360
  dHp = 2 * sqrt(C1p*C2p) * sin(dhp*PI/360)          // sin(半角)
  Lbar = (L1+L2)/2;  Cbarp = (C1p+C2p)/2
  if C1p*C2p == 0: hbar = h1p + h2p
  elif abs(h1p-h2p) <= 180: hbar = (h1p+h2p)/2
  elif (h1p+h2p) < 360:     hbar = (h1p+h2p+360)/2
  else:                     hbar = (h1p+h2p-360)/2
  T = 1 - 0.17*cos(hbar-30) + 0.24*cos(2*hbar) + 0.32*cos(3*hbar+6) - 0.20*cos(4*hbar-63)   // 角度制三角函数
  dTheta = 30 * exp(-((hbar-275)/25)^2)
  RC = 2 * sqrt(Cbarp^7/(Cbarp^7+25^7))
  SL = 1 + 0.015*(Lbar-50)^2 / sqrt(20 + (Lbar-50)^2)
  SC = 1 + 0.045*Cbarp
  SH = 1 + 0.015*Cbarp*T
  RT = -sin(2*dTheta * PI/180) * RC
  return sqrt( (dLp/SL)^2 + (dCp/SC)^2 + (dHp/SH)^2
             + RT*(dCp/SC)*(dHp/SH) )
```

### 3.3 最近邻匹配（逐格）

```
function matchToPalette(cells: sRGB[], paletteLab: Lab[]): Pattern
  for each cell color c:
    lab = srgbToLab(c)
    best = argmin over paletteLab 的 ciede2000(lab, p)   // 并列取索引小者
    pattern.cells[i] = best
```

性能（网格 ≤ 250×250=62.5k 格、色表 ≤ ~300 色）：
- 优先用 **ΔE76（Lab 欧氏，快 ~50×）做初筛**：对每格先算 ΔE76 取前 k=8 候选，再对这 8 个算完整 ΔE2000 定最优 —— 结果与全量 ΔE2000 在绝大多数格一致且差异 <0.1 ΔE，工程上可接受（在代码注释中说明，并保留"全量精确"开关）。
- 或整格循环中 early-exit（当前最优为 0 直接短路）。二选一即可，P0 用 ΔE76 初筛方案。
- `transparent` 类色（若色表含"透明豆"）**不参与最近邻匹配**（只可由用户显式选择/橡皮擦用）。

## 4. 限色：按用量 + 关键色保护（不是粗暴取前 N）

```
function limitColors(pattern, palette, maxK):
  used = 按 pattern.cells 统计每色索引用量
  if used.size <= maxK: return pattern
  // 1) 保护集 P：对"被用到的颜色"计算
  //    - 暗色：匹配到该色的格的"源代表色"平均 L* 最小的一批（占总用量 ~4%，至少 1 色）
  //    - 亮色：平均 L* 最大的一批（同 4%）
  //    - 饱和：平均 C* = sqrt(a²+b²) 最大的一批（同 3%）
  //    实现：收集每个 used 色的 平均 L*/平均 C*/像素数（匹配时顺带累加，避免二遍全扫）
  // 2) 候选集 = used \ P；按 (像素数 desc, 色号 asc) 排序
  // 3) 结果 = P ∪ 候选前 (maxK - |P|) 个
  // 4) 未被选中的格：在这些格的颜色被淘汰后，重匹配到"结果集"中 ΔE2000 最近者
  return remap(pattern)
```

诚实声明（写入代码注释与 UI 帮助）：该算法是确定性启发式，保证关键深/亮/饱和细节不因"取前 N"被整体抹掉；不做全局最优迭代（v1.1 可上贪心逐色淘汰）。

## 5. 抖动（可选，默认关）：Floyd–Steinberg

仅当用户开启且未开限色。在**网格分辨率**上做蛇形扫描量化到色表：
```
function ditherFloydSteinberg(cellsLinear: [W*H], palette):
  // 误差在 线性RGB 空间传播；quantize = 该色到色表 ΔE76/ΔE2000 最近色
  for gy in 0..H-1:
    if gy 偶: for gx in 0..W-1    // 左→右
    else:     for gx in W-1..0    // 右→左
      i = gy*W+gx
      chosen = quantize(cellsLinear[i], palette)
      err = cellsLinear[i] - paletteRgb(chosen)         // 线性空间向量
      pattern.cells[i] = chosen
      // 误差按 7/16,3/16,5/16,1/16 扩散到 (右/下一行左中右)（按扫描方向取"前方"邻居）
      向当前扫描方向尚未处理的邻居加 err*权重
```
UI 注明：抖动会制造"两格交替"的纹理，适合照片，不适合想要干净色块的图案。

## 9.1 孤立噪点清理 speckleClean(noiseMax=2, ΔEthr=30)

目标：消除 1–2 格的孤立杂色（"眼睛渐变高光/手指分叉"里无价值的小块），并**保住明显成块的细节**（眼睛等成片区域不受影响）。

```
输入 Pattern（cells 为色板索引）
label[] = 4-邻域连通域标记（同色索引视为同域）；记录 每域: 色索引、格数、边界邻居色索引计数
对域按 (格数 asc, 色索引 asc) 排序，逐个处理：
  若 域格数 <= noiseMax：
    c2 = 该域边界邻居中出现次数最多的色索引（并列取索引小）
    若 ΔE2000(palette[c], palette[c2]) <= ΔEthr：该域全部格 → c2
（处理完一批后域合并自然发生；单遍即可，不迭代到收敛）
```
- 保护规则：**不合并**"该色全图仅此一域"的关键色（如只有 1 块且格数 > noiseMax 的色不受影响；本算法只动小域，天然保护大块）。
- 与底色差异极大的 1 格（ΔE > ΔEthr，如深色瞳孔）**不合并**（保留了眼睛瞳孔，符合"别把特征抹掉"诉求）——默认 ΔEthr=30 可调 20–40。
- UI：开关 + 阈值滑杆"清除 ≤N 格的孤立点"（1/2/3，默认 2）；卡通/插画默认开。

## 9.2 暗部简化 shadowSimplify(level: 0 关 | 1 标准 | 2 强)

目标：把"灰黄/土黄/褐黄的零散暗部"统一成 1 个深棕暗部（拼豆玩家习惯），同时不误伤明显彩色暗部（深红/深蓝等）。

```
// 1) 收集 Pattern 中已用色；找出候选"统一暗部锚点" d*
//    已用色里 L* 最低的色为主锚点候选；若其 C*（饱和）低（灰/棕类），以其为 d*；
//    否则取已用色中 L*<45 且 C* 最小者。
// 2) 对每个已用色 c（c != d*）：
//    if L*(c) < 45 且 ΔE2000(c, d*) <= 阈值T（level1=18, level2=28）→ c 重映射为 d*
//    （彩色暗部因与 d* 相距远而保留）
// 3) 重映射后若有格指向被合并色，全部指向 d*。
// 4) 说明：若整图没有足够暗的色（如浅色图），步骤 1 找不到 d* → 本处理跳过（幂等）。
```
- 用户反馈中的"1 种深棕/深褐做暗部"即 level 1 默认效果；level 2 额外吸收偏灰暗部。
- 判定暗部用 `L*<45` 阈值可在实现中作为常量（注释说明依据：MARD 深棕系 L*≈25–40）。
- UI：三档下拉"暗部：关 / 标准 / 强"；卡通插画默认标准。

## 9.3 智能限色 clusterLimit(K, protect=true)（取代 §4）

目标：把"亮黄/主黄/深黄/灰黄"这类同色系过渡压到 ≤3 层，全图 ≤K 色 —— 而不是按用量粗暴取前 N。

```
输入：已映射 Pattern + 全色板 Lab + K（8/12/16/24/36…）
// Step 1 统计 used：已用色索引 → 用量
if used.size <= K: 直接返回（无需聚类）
// Step 2 色相族分组 hueFamily：
//   a* b* 平面角度 hue = atan2(b*, a*)（度，0–360）；|C*| 很小(<8)判为"灰族"
//   将 used 色按 hue 排序后，把相邻（差 <= 20°）且 C* 均 >8 的并入一族；
//   每个灰系色自成一族（不与他人混）。
// Step 3 族内分层 quota：
//   族配额 = max(1, round(族用量占比 * K))；配额超限时先保证族内
//   保留 [最亮 L* 最大者, 最暗 L* 最小者]，其余按 L* 等距选代表色，其余成员并入
//   与自身 ΔE2000 最小的保留代表色（在保留集内最近邻，不用板外色）。
// Step 4 总色数仍 > K 时：按"族配额从大到小依次减 1，且该族内最接近的
//   两个相邻 L* 层先合并"迭代，直到 used' <= K（确定性：按配额降序、层间 ΔE 升序）。
// Step 5 保护（protect=true，沿用 §4 语义）：强制保留"实际用到的最暗/最亮/最饱和"
//   各若干（若被 Step3/4 合并则撤销其所在合并，代价 = 让别的层多合一层）。
// Step 6 未被保留的格在最终保留集上重匹配（ΔE2000 最近，保留色集内）。
// 输出：Pattern'（色数 <= K）；统计随动。
```
- 效果度量（验收用）：同色相族内层数 ≤3；"黄色系"在卡通样例中应收敛为 ≤3 层。
- UI：快捷 chips 24/48/72/96/120/144/168/221/313 + 自选数字（上限 400）；说明文字"自动按色系分层压缩，非简单取前 N"（v1.2.1 修订）。
- golden：新增 fixture（黄色渐变图 64×64 合成）断言聚类后色数 ≤ K 且暗部单层。

## 9.4 自动描边 outline(1px, τ=0.18)

目标：给内容/背景或高对比交界加 1px 深色轮廓，便于数格、避免软边看错行。

```
// 1) 描边色选择：在"已用色 ∪ 色板"里取 L* 最小且 C* 不太大的深色作为 outlineIdx
//    （优先取 Pattern 已用的最深色，避免新增颜色；若已用最深 L* > 30 且色板内有 L*<25 的
//     solid 色则允许新增 1 色，UI 明示"K+1"）。
// 2) 边缘判定：对每个格 gx,gy（含背景/空格 -1），计算其与 4-邻域（出界按背景 Y=bg）的
//    线性亮度 Y（§6.2 的 Y）差；若任一邻居 |ΔY| > τ（默认 0.18，可调 0.10–0.30）→ 标记。
// 3) 落色：被标记的"前景内容格"整格改为 outlineIdx（1px = 自身格变色，不膨胀外扩）。
//    （空格 -1 不改成轮廓色，轮廓落在内容格边缘一侧，保证数格不变）
// 4) 已在 H3 限色后执行，因此最终色数 = K（若用了板内已用深色）或 K+1（新增深色）。
// 5) 若 Pattern 全图仅 1 色或整图无边缘（|ΔY| 全部 <= τ），输出不变（幂等）。
```
- UI：开关"深色轮廓 1px"+ 阈值滑杆；卡通插画默认开；照片默认关。
