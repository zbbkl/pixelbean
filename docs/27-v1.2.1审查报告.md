## 2. 改动核验细项

- **R2 根因确认**：`app.css:119 .app-body { flex:1 1 0 }` 为基态；手机列 flex（`app-shell{display:flex;flex-direction:column}`）下该 `flex-grow:1` 使内容填充到 `100dvh - header`，越过固定底栏 `nav` 高度。`mobile-viewer.css:48 flex:0 0 auto` 使 `.app-body` 回归显式 `height:calc(100dvh - header - nav)`，底边恰好落在 `nav` 顶边。修复**必要且精确命中**。
- **classifyRegion 分支完备性**：`fracW<=0.35 && fracH<=0.35`→dot；`fracW<=0.35 && fracH>0.35`→vline；`fracW>0.35 && fracH<=0.35`→hline；否则（双块状 + share≥0.30 + ΔY≥0.15）→boundary。边界格仅在此可达，符合「块状、平衡、高对比」设计。
- **meanF/meanM 语义**：`smallSide`=少数侧→`meanF`；`otherSide`=多数侧→`meanM`；与 docs 的 F/M 命名一致。
- **worker 兼容**：`convert.worker.ts:18` 仍 `convertPipeline(source, options, palette)` 三参，`regionCleanEnabled` 默认 false；新边界仲裁经 features 开关天然生效（照片默认开），regionClean 不进入 worker 路径。
- **后端无残留**：grep 确认旧底板（29/39/116）、旧 chips（8/12/16/24/36）、`onClick={cancel}`/`function cancel` 均无；`targetMode:'custom'` 仅存在于「手动改参→自定义」联动逻辑（保留，符合 docs/25 §0.1 澄清）；`targetMode:'cartoon'` 仅存在于 cartoon 预设自身。

## 3. 度量与效果（`.tools/v12dot1-report/metrics.json` + 截图）

- **色数不膨胀**：卡通 on/off 均为 9 色、占用 2494；照片 on/off 均为 72 色、占用 2668。边界仲裁只在既有色号内重分配，未引入新杂色。
- **效果方向**：卡通模式肖像 22 色（on）vs 21 色（off）——on 版保留更多中间调棕色、黑色占比更低（H07 38% vs 47%），更接近「细节保留」目标；off 版更激进的 posterize。其余栅格级差异为 1–2 格（regionClean 单遍仅并 2–3 格）。
- **性能**：照片 on（默认）47.2ms vs off 38.4ms（+8.8ms）；卡通 on 98.5ms vs off 67.8ms（+30.7ms）。绝对耗时均 <100ms，仍在 docs/19 Q4「同数量级」预算内；默认照片路径已是 on（自身开销 47.2ms，可接受）。
- **目检局限**：`photo-*`/`cartoon-*` 为 300×240 肖像，不能覆盖任务书强调的「眼/身/腿」真实角色图目检；`.tools/test-img/result-v1.1-cartoon.png` 与 609×814 卡通样例的逐区对照需在真实角色图上由人复核（docs/26 亦列为残余风险）。
