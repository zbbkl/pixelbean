## 3. 算法优化设计（R6）——色块识别与还原提升

### 3.1 问题与根因定位

对比原图在**眼睛、身体、腿部**出现“色块丢失/识别错误”，对应管线三个阶段的典型根因：

1. **降采样混色**：`average` 把跨区域边界格（肤色/衣/腿交界、眼周高光）平均成“中间脏色”，既不属于任何一侧 → 视觉上色块错位、边界糊。
2. **细节被稀释**：小面积高对比特征（瞳孔高光、发丝间隙、鞋袜边线）在平均里占比过低被洗掉 → “丢失”。
3. **匹配/后处理的次生问题**：边界脏色再经最近邻匹配落到某个非两侧的邻近色；K 限色/暗部合并进一步抹平中间调层次（身体/腿的明暗分界）。

v1.2 的 `features.ts`（细线/点特征 + 保护掩码）已覆盖根因 2 的多数情形且**照片预设此前默认关闭**；根因 1（平衡型双类边界格）当前**明确未处理**（classify 对 `share>0.35 且非条带` 的“整块”返回 null → 走 average）。

### 3.2 开源借鉴清单（逻辑借鉴，代码红线见 docs/00 §1）

| 项目（许可证） | 借鉴的算法逻辑 | 在本项目的落地 |
|---|---|---|

| Zippland/perler-beads（AGPL-3.0，仅思路） | 色差用感知空间（Oklab/ΔE）匹配 + “先匹配后微调”产品流 | 匹配层保持 CIEDE2000（docs/03 §3），不改；借鉴其“结果可再调”不引入 |

### 3.3 新算法设计（确定性、DOM-free、additive）

#### A. 平衡双类“边界格”仲裁（核心，改 `features.ts`）

现状：`classifyRegion` 只在“特征类为少数（条带/点）”时返回候选；双类接近平衡（`share∈[0.35,0.5]`、块状分布）返回 null。

增强规则（features 开启时对每格生效）：

```
输入（每格，区域像素）：
  // 沿用现有亮度双类迭代(2 轮)得到 M(多数侧)/F(少数侧) 与各自线性均值→sRGB
  ΔY = |Y(M)-Y(F)|；share = |F|/n
附加判据（本版新增）：
  if ΔY >= BOUNDARY_DE_Y(0.15)              // 高对比、非渐变
     && share ∈ [BOUNDARY_SHARE_MIN=0.30, 0.50]
     && 形态为块状（fracW>FRAC 且 fracH>FRAC，沿用 0.35）：
        → 标记候选 kind='boundary'，携带 meanRGB(M)、meanRGB(F)
边界仲裁（网格级，逐格）：
  for 每个 'boundary' 格 g：
     nb = 4-邻中已产出 base 色的格子（跳过空格/越界）
     dM = mean_{n∈nb} ΔE2000(meanRGB(M,g), baseRGB(n))   // 与周围主体色的差异
     dF = mean_{n∈nb} ΔE2000(meanRGB(F,g), baseRGB(n))
     if nb 为空: 保留 base（孤立格不做猜测）
     elif dF + BOUNDARY_MARGIN(3.0) <= dM:   // 少数侧明显贴合周围 → 说明 avg 该取少数侧(细部穿格)
         base[g] = meanRGB(F,g)
     elif dM + BOUNDARY_MARGIN(3.0) <= dF:   // 多数侧贴合 → 两侧不换(avg 已近 M,保持 base 亦可,为确定性直接置 M)
         base[g] = meanRGB(M,g)
     else: 保留原 base（两侧都不贴 = 真空地，不动，避免引入噪声）
  // 不写 protect 掩码：boundary 仲裁是为“边界正确”，不是“特征形状”
输出不变：{ cells, protect }
```

- 常量集中定义并注释依据：`BOUNDARY_DE_Y=0.15`（人眼可感知的明度差下限）、`BOUNDARY_SHARE_MIN=0.30`、`BOUNDARY_MARGIN=3.0`（ΔE2000 判别余量，低于此判“无定论”）。
- 确定性：均值迭代 2 轮 + 并列按 g 索引序；无随机。
- 与既有规则关系：细线/点特征处理在前（优先级更高），boundary 仅处理“整块平衡”格；整块失衡（share>0.5 或 <0.3）仍走原逻辑。
- 复杂度：每格一次双类统计（已存在），仲裁循环 O(格数)。

#### B. 匹配后“区域一致性多数修正”（可选开关，`src/core/post/regionClean.ts` 新模块）

目标：纠正“整体区域内部零星错色”（身体/腿部大色块里 1–2 格异色，肉眼明显但单格 ΔE 小、speckle 阈值放过的情形）。

```
regionClean(pattern, palette, protect: Uint8Array|null = null,
            deThr = REGION_DE(8.0), minSame = 3): Pattern
  // 单遍：对每个内容格 c(非 protect、非 -1)：
  //   统计其 4-邻中同色索引的众数 (c2, cnt)
  //   if cnt >= minSame 且 ΔE2000(palette[c], palette[c2]) <= deThr
  //      → cells[i]=c2
  // 不改动：已连通成片(邻域无 3 同色异格)的格、protect 格、空格。
  // 幂等性：合并后不再迭代；若没有任何格被改 → 返回原 pattern(引用相等)
```

- 默认关闭（不进任何模式预设），UI 不加开关，仅由算法接入方（Codex 联调）在自定义管线里用新测试验证效果；**若对照效果显著且无副作用，再由 Claude 审查后在 §6.2 决议是否并入照片预设**。→ 控制风险，避免本版盲目改变默认输出。
- 新增 UiSettings/ConvertOptions 字段**本版不加**（regionClean 先作为 `convertPipeline` 内部可编程选项，测试直调函数）。

#### C. 轮廓连续性微调（可选，`outline.ts`）

- 现状：`outline` 对亮度差 >τ 的格落色，边缘断点/孤立落色由 speckle 兜底。
- 可选微调（默认 τ 与行为不变）：落色后对“被标记格”做一次 4-邻**连续校验**——若某格 4-邻中没有任何其它被标记格且自身两侧均为同色大块（既非细线也非角点），撤销该格落色，防止孤立“杂点轮廓”。是否并入以对照效果为准（同 B 流程）。
