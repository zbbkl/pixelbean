## 2. 分步实施（每步 `npm test` 全绿再进下一步）

> ⚠️ 环境提示：若在 Windows 沙箱用 `npx vitest`/`npm test` 遇到 `spawn EPERM`（esbuild service 依赖 named-pipe，被沙箱拦截），**换用宿主环境跑**（`npm test`），或在配置里给 vitest 设 `--pool=forks` 规避；不要用 `npx esbuild`（同样 EPERM）。

1. **E1 + E1d**：`downsampleDominantV2`（Lab 桶 10×12×12、`emptySmooth=0.5`、稀疏回退 `NEARLY_EMPTY_PX=4`）+ 既有 `downsampleDominant` 保留 + `downsample()` dominant 分支改调 V2 + `modePresets`/`state.tsx` 默认 dominant + 单测 + 回归旧 golden（只允许"杂色更少"方向）。
2. **E2**：`classifyChromaFeature`（`CHROMA_HUE_GAP=25°`、`CHROMA_DC_MIN=0.12`、`CHROMA_DOT_MIN=0.10`、`CHROMA_DOT_MIN_TOTAL=3`）+ 特征均值回采 + 单测；确认与亮度特征/边界仲裁不冲突。
3. **E3**：`mergeAdjacent`（`MERGE_DE=6`、`MERGE_MIN_AREA=3`、`MERGE_MAX_AREA=40`）+ `convertPipeline` 接入（仅 featuresEnabled 且照片路径，置于 speckle 前）+ 单测；确认不跨越 protect/空格、不新增色号。
4. **E4**：`softEdgeArbitrate`（`SOFT_MARGIN=2.0`）+ 单测；确认与 v1.2.1 高对比 boundary 仲裁互补、无骤变异常。
5. **E5**：`ciede2000Weighted`（不改原 `ciede2000`）+ `match.ts` 内部 `nearestPaletteIndexWeighted` 按 `C*<25` 用 `{kL:0.85,kC:1.05,kH:1.15}` + 单测；既有 `ciede2000`/`nearestPaletteIndex` golden 不回归。
6. **P1 性能**：验证 120×120 转换耗时；若超 2s 定位热点（预期在匹配层 291 候选 ×14400 格）。

## 3. 性能保障（P1，交付验收线）

- **硬目标**：120×120 方形板（14400 格）全管线转换 ≤ **2s**；移动端无肉眼卡顿（>100ms 需标注）。
- **口径**：计时起点 = 用户触发转换（`convertStart`）到 `pattern` 产出的 worker 内耗时；不含首帧渲染与色板 precompute（色板 Lab 已缓存，docs/03 §3）。
- **预算分配（参考）**：采样（E1 Lab 桶化）+ 特征（E2/E4）+ 匹配（E5，291 ×14400 ≈ 4.2M CIEDE2000）为主；合并（E3）O(格数)。
- **优化预案**：若匹配层超预算，优先给 `nearestPaletteIndexWeighted` 加**候选预筛**（保留现有 ciede76 top-k=8 粗筛再精排，见 docs/28 §6.4 说明），或缓存每格 Lab（已存 `MatchDetails.labs`）；`MAX_CELLS=150k` 不变。
- **测录**：记录 sample/match/merge/total 各段耗时到自测报告。
