# 01 · 产品规格与验收清单

> 本文档是 PixelBean v1 的**需求契约**。Codex 按此实现，Claude Code 按此审查，人工按此验收。
> 冲突时以本文档 + `docs/02`（架构）+ `docs/03`（算法）+ `docs/04`（数据）为准；先改文档再改代码。

## 1. 产品定位

一句话：**把任意图片转成拼豆图纸 —— 每个格子标注该用哪个色号、总共每种色号各需要多少颗，并能导出/打印图纸。**

- 纯前端、本地优先：图片不出本机，无后端、无账号（第一版）。
- 面向用户：拼豆玩家（Perler/Hama/Artkal/MARD/国产拼豆用户）。
- 诚实原则：屏幕色与真实豆色有偏差，**图纸以"色号"为准**（按官方/社区色号标注）；UI 中给出相应提示，不承诺所见即所得。

## 2. 用户故事（v1 覆盖的）

1. 作为玩家，我上传一张照片/表情包/logo，选好我的豆子品牌，得到一张每格标好色号的图纸，按图拿豆。
2. 作为玩家，我告诉系统"图纸长边不要超过 58 格"，高度按原图比例自动算出，不被拉伸变形。
3. 作为玩家，我只想用某种豆子品牌最常用的几十色，可以限制用色数量并保留深色/亮色细节。
4. 作为玩家，我打开图纸时能随时看清某一格是什么色号（悬停/放大/标注开关）。
5. 作为玩家，我拼之前想知道每种色号要买几颗，能导出/打印购物清单。
6. 作为开发者/爱好者，我导入自己的色号表（自定义品牌 JSON），用同样流程生成图纸。

## 3. v1 功能范围

### 3.1 功能清单（P0 = 第一版可演示必须；P1 = 强烈建议；P2 = 留作 v1.x）

**图片输入**
- P0 拖拽/点选上传图片（PNG/JPG/WebP/BMP/GIF 首帧）；图片全在本机处理。
- P0 内置 2–3 张示例图（一张照片、一张像素风角色），便于零输入演示。
- P0 透明背景处理策略（垫白/垫黑/保留透明用专用"空"标记）默认垫白。

**参数控制（P0 全部）**
- 品牌选择（内置色表下拉，见 `docs/04`；当前先 MARD 全量 291 色，其余品牌数据合规后追加，下拉先只放已就绪项 + "导入自定义色表"）。
- 网格尺寸：两种输入并存 —— (a) 常用预设按钮（29×29 / 39×39 / 58×58 / 长边 32 / 长边 64 等，做成可配置常量表）；(b) 任意格数（输入"长边格数"，锁宽高比自动算另一边）。**语义统一为"长边=N 格"，绝不非均匀拉伸**。
- 降采样模式：`面积平均`（默认，照片适用）/ `主导色`（适合本来就近似的图/线稿）。每种模式给一行说明文字。
- 最大用色数（可选，默认关=不限）：输入 N（如 24/48/96），配合**关键色保护**算法（见 `docs/03` §4），不要粗暴取前 N。
- 抖动：`无`（默认）/ `Floyd–Steinberg`（完整实现，仅当用户选择"抖动"时生效；UI 提示抖动适合照片、不适合纯色块风格）。
- 预处理滑杆：亮度 / 对比度 / 饱和度（-50%～+50%，默认 0），实时作用于转换输入（P1，若 Codex 时间紧可后置但面板留占位）。

**图纸预览（P0）**
- 渲染方式：Canvas 整图绘制（不做数千 DOM 格），支持滚轮缩放 + 拖拽平移；缩放时**格线/标注按需显示**（格子屏幕尺寸 < 阈值只显示色块；> 阈值叠加色号文字与格线）。
- 逐格色号标注开关；标注文字颜色自动按底色亮度取黑/白保证可读。
- 悬停单格：高亮 + 顶部信息条显示 `品牌-色号 / 色名 / HEX`。
- 原图 ↔ 图纸对比：左右分栏或半透明叠加（P1）。
- 大图保护：网格超过上限（如 250×250 或像素预算）给出确认或提示，转换在 Worker 中可取消。

**用量统计与购物清单（P0）**
- 表格：色号缩略色块 + 品牌码 + 色名 + 数量 + 占比；默认按数量降序。
- 可勾选"我已有"完成度，汇总"需购买色号数 / 总豆数"。
- 一键复制为文本清单；导出 UTF-8 CSV（含 BOM，Excel 中文不乱码）。

**导出（P0 = PNG + 打印；P2 = PDF）**
- PNG 图纸：`带色号标注` / `纯色块` / `带坐标辅助线` 三种（单选导出）。
- 打印图纸：`@media print` 样式表，把图纸按 A4 分页 + 每格角标色号，用户浏览器"打印 → 另存为 PDF"即得 PDF（P2 再考虑 jspdf 直出）。
- 工程保存：当前参数+图（缩略/本地）存 localStorage 草稿，刷新可恢复（P1）。

**自定义色表导入（P1）**
- 粘贴/上传符合 `docs/04` Schema 的 JSON（校验并给出错误行提示）；存 localStorage；与内置色表并列可选；可删除。

### 3.2 明确不做（本版）
- 后端 / 账号 / 云存储 / 分享链接（第一版纯静态）。
- 逐格手动编辑画笔/橡皮、逐色上色助理、图案识别补码、底板多板拼接布局（进 v1.1 路线图，架构上预留：编辑能力依赖"工程 JSON + PatchOp"设计，见 `docs/02`）。
- AI 图片增强（调研显示有项目做"AI 优化原图"，属另一主题，不进 v1）。
- 移动端 App / 小程序。

## 5. Definition of Done（Codex 阶段 2 的验收标准）

阶段 2 交付时必须全部满足，Codex 自测并附结果：
- [ ] `npm install && npm run dev` 一条命令起服务，浏览器打开无控制台报错。
- [ ] 内置示例图可直接出图：选品牌 MARD → 长边 58 格 → 得到色号网格图；图纸与原图比例一致（无拉伸）。
- [ ] 上传真实照片（含透明 PNG、纯色图、线稿图、超宽横图各 1 张）均不崩溃；透明图默认垫白后无异常黑边。
- [ ] 逐格标注可开关；标注文字可读性（黑/白字按亮度切换）肉眼抽查通过。
- [ ] 用量统计：总数 = 网格格数（如 58×N）；各色号数量求和 = 总数（与算法输出一致性自检通过）。
- [ ] 导出 PNG 与打印视图可见、内容与预览一致；CSV 用 Excel 打开中文不乱码。
- [ ] 大网格（≥200 格长边）转换可在 3s 内完成或显示进度且可取消。
- [ ] 核心算法有单元测试（golden fixture，禁随机），`npm test` 通过。
- [ ] 未引入任何来自 AGPL/GPL/无证仓库的代码或数据（红线见 `docs/00`）。

## 7. 非功能要求

- 性能：转换在 Web Worker；主线程不阻塞；渲染 Canvas 用 `requestAnimationFrame` 分块。
- 可维护：核心算法模块零 DOM 依赖、可单测；模块文件 < 400 行（吸取 Zippland/Pindo 单文件巨兽教训）。
- 兼容：现代 Chrome/Edge/Firefox/Safari；移动端可用但非重点。
- 可部署：`npm run build` 产出纯静态 `dist/`，可直接放 GitHub Pages / Vercel / Nginx。

## 8. 新增功能（对应 docs/03 §9.1–9.5）

| ID | 功能 | 说明 | 默认 |
|---|---|---|---|
| A | **智能限色**（升级原"最大用色数"） | 按色相族×明度层聚类压到 ≤K；UI 快捷 chips **8/12/16/24/36** + 自选数字；说明"按色系分层压缩，非简单取前 N" | 随模式 |
| B | **暗部简化** | 三档下拉：关/标准/强；把相近灰黄/土黄暗部并入统一深棕 | 卡通=标准 |
| C | **孤立噪点清理** | 开关 + 滑杆"清除 ≤N 格孤立点"(1/2/3) + 色差容差滑杆(20–40) | 卡通=2 |
| D | **自动描边** | 开关"深色轮廓 1px" + 阈值滑杆；限色后执行，色数 = K 或 K+1 | 卡通=开 |
| E | **一键目标模式** | 照片/卡通插画/线稿/像素表情包 下拉；改动参数后自动变"自定义" | 卡通/插画 |
| F | **色板扩展** | 新增 Perler std、Hama midi（数据链路见 docs/04；UI 标来源可信度） | 随选择 |
| G | **底板预设补 116** | boardPresets 增加 116×116；contain 语义不变（无半格） | — |

交互顺序固定：噪点清理 → 暗部简化 → 智能限色 → 描边（docs/03 §9.0）；"限色"与"抖动"同时开启时抖动置灰（沿用 v1 纪律）。
