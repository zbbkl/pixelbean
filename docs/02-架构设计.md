# 02 · 架构设计

> 用途：定义模块边界与接口形状，让 Codex 能**分模块实现并逐步自测**，让 Claude Code 有明确的审查对象。
> 硬性工程纪律（吸取 Zippland page.tsx 135KB / bead-grid app.js 264KB 单体教训）：**任何源文件 ≤ 400 行**；核心算法零 DOM；全程确定性。

## 1. 技术选型与理由

| 项 | 选择 | 理由 |
|---|---|---|
| 构建 | **Vite 5/6 + React 18 + TypeScript** | 纯前端静态产物；主流栈降低多 Agent 实现/审查的出错率；画布重绘由我们控制，React 只做状态与面板 |
| UI | 无组件库，纯 CSS + 原生控件 | 少一个依赖就少一份 Agent 幻觉空间；自定义控件样式符合工具类产品气质 |
| 转换 | **Web Worker**（`new Worker(...,{type:'module'})`） | 主线程不卡；大图可取消 |
| 颜色/算法 | 自研 `src/core/`（零依赖） | 算法是本产品核心价值，且调研证明零依赖完全可行 |
| 测试 | **Vitest**（core 单测 + golden fixture） | 确定性回归；Playwright e2e 可选（P2） |
| 导出 | Canvas.toBlob PNG + 打印样式表（浏览器"打印→PDF"） | v1 不引 jspdf；P2 再评估 |
| 部署 | 纯静态 `dist/` → GitHub Pages / Vercel / Nginx | 无后端零运维 |

依赖清单（目标 **运行时零依赖或 ≤1**；devDeps: vite/typescript/vitest/@vitejs/plugin-react 等即可）。

## 3. 核心类型与模块接口（Codex 照此实现，勿改签名；要改先改 docs）

```ts
// src/types.ts
type PaletteId = string
type BgMode = 'white' | 'black'
type DownsampleMode = 'average' | 'dominant'          // 默认 average
type DitherMode = 'none' | 'floyd-steinberg'          // 默认 none
interface ConvertOptions {
  paletteId: PaletteId
  width: number; height: number        // 目标网格（已由 §geometry 算好，锁宽高比）
  bg: BgMode
  mode: DownsampleMode
  maxColors: number | null             // null=不限（默认）
  dither: DitherMode                   // maxColors 非空时忽略（UI 置灰）
  adjust?: { brightness: number; contrast: number; saturation: number } // 默认全 0（P1）
}
// 网格尺寸语义在 UI 层完成：preset(方形, contain 留空) 或 custom(长边=N) → {width,height}
interface Pattern {
  paletteId: PaletteId
  width: number; height: number
  cells: Int16Array                    // 每格 = palette 色索引；-1 = 空(留空行/背景空)
  codes: string[]                      // index→code（对齐 labPalette 顺序）
  options: ConvertOptions
}
interface ColorStat { index: number; code: string; name: string | null; hex: string | null; count: number; ratio: number }
```

## 4. 数据流与状态

```
上传/示例图 ─→ createImageBitmap → {bitmap,width,height}
options(面板) ─(防抖 300ms)→ 派发 convert(id)
  └→ worker: convertPipeline(ImageData/ImageBitmap, options, paletteData)
       → Pattern(cells:Int16Array transferable) + stats
  ← 主线程: 校验 id 最新 → 存 state.pattern → StatsPanel 渲染表
                              → PreviewCanvas 重绘（drawGrid）
导出: 复用同一 drawGrid 到离屏大 canvas（不依赖屏幕缩放）→ toBlob / 打印
```

- **state 单一来源**：`state = { image, options, pattern, stats, lastSeq }`；`useReducer`。旧转换结果按 `seq` 丢弃（worker 无法取消 JS 循环时，靠 seq 校验保证 UI 只采纳最新）。
- 图片进 worker：`OffscreenCanvas` 可用则 transfer，否则 `ImageData`（`data.buffer` transfer）。v1 允许降级：worker 内直接用主线程传入的 ImageBitmap 的像素。
- 上限保护：`maxCells = 150_000`（≈ 长边 390 方形）；超限 UI 确认或拒绝；最大原图边 ≤ 12000px（先压缩取样再进 worker）。

## 5. 渲染（PreviewCanvas）要点

- 单 `<canvas>`；内部逻辑坐标 = 格坐标；`zoom = cellPx（每格像素）`，范围 1..96（`cellPx<1` 时缩小整体画面）。
- 滚轮缩放以光标为锚点；空格/中键拖拽平移；触控板双指平移（移动端基础支持）。
- 绘制 LOD（docs/03 §6.3）：cellPx<14 纯色块；≥14 加格线+色号文字；文字黑/白按相对亮度（§6.2）。悬停命中 = 逆变换取格 → HoverBar。
- 设备像素比处理：canvas 物理尺寸 = css×dpr；`ctx.setTransform` 统一管理，不用 `scale` 拼接避免模糊。
- 格子数大（> 40k）时 `drawGrid` 按行分块 `requestAnimationFrame`，避免单帧卡顿；v1 可接受一次性画完（≤150k 格 Canvas 2D fillRect 数量级没问题，实测不足再分块）。

## 6. Worker 协议（convert.worker.ts）

```ts
// → worker: { seq, kind:'convert', img:{width,height,data?|bitmap?}, options, palette: LoadedPalette(JSON+lab 由 loader 在主线程算好传入，worker 只消费) }
// ← main:  { seq, kind:'result', pattern:{width,height,cells(Int16Array transfer),codes}, stats }
// ← main:  { seq, kind:'error', message }
// 取消：主线程递增 seq 并丢弃过期结果；不在 worker 里做抢占式取消（P1 可加 SharedArrayBuffer 标志）
```

## 7. 工程文件说明（给 Codex 的顺序敏感信息）

- `src/core/**` 不允许 `import` 任何 `src/app/**` 或 DOM API；`render/drawGrid.ts` 只接受 `CanvasRenderingContext2D` 参数（可单测：用 `node-canvas` 或 mock 上下文做形状断言，P1）。
- golden fixture：`tests/fixtures/*.png`（小尺寸 64×64 合成图，无版权）+ `expected.json`（Pattern cells+统计的 sha-256）。改算法必须同步更新 fixture 并写明原因。
- `npm run dev` / `npm run build` / `npm test` 三条命令为验收基线（docs/01 §5）。

## 8. 路线图钩子（本版不实现，但架构上不要堵死）

- **编辑能力**：Pattern 已把 cells 与 palette 解耦 → v1.1 加 `PatchOp[]`（set/erase/floodFill）与撤销栈，落 localStorage + 工程 JSON（RLE 压缩 cells，不内嵌原图）。
- **多板拼接**：`Pattern` 可带 `board: {板型, 摆放(x,y)}[]` 元数据 → 渲染层加辅助线即可。
- **特殊色支持**：loader 保留 kind=special/transparent，UI 加"手动上色模式"即可用。
- 云端 AI 增强（火山即梦型）与后端分享：属独立方向，v1 架构不引入任何服务端假设。
