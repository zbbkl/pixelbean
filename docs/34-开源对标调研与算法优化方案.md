# 34 · 开源对标调研与算法优化方案（PixelBean v1.2 商用冲刺）

> 调研/分析时间：2026-09。执行主体：DeepSeek Harness（独立自主完成）。
> 目标：为 PixelBean v1.2 冲刺「商用级输出质量」，独立完成 **开源对标调研 → 测试样本选取 → 效果自测对比 → 问题定位分级 → 兼容现有管线的商用级算法优化方案** 全流程。
> 结论性质：本方案中的「自测对比」为**确定性、逐行走查的算法级模拟**（用可复现的合成测试样本 + 对现有源码逐行推导），非 GUI 截图对比；已在 §0.3 明确边界与可复用性。

## 0. 摘要与阅读指引

### 0.1 一句话结论

PixelBean v1.2 的管线在**结构**上已对齐商用同类（CIEDE2000 匹配 + 主导色采样 + 特征保护 + 连通域合并 + 智能限色），但在**出厂默认路径（照片/卡通）**上存在 3 个 P0 级算法缺陷：**(1) E1 主导色采样的「空桶平滑」亮度轴失效（代码级 bug）；(2) 主导色采样把柔和渐变切割成硬 2 类，产生明显色带；(3) 小特征保护下限过高，微小但有意义的特征被吞掉。** 这三者正是奶龙类 3D 柔边渐变对象在商用质量下暴露的最痛问题。修复后即可达到同档开源旗舰的整体质量，并在「渐变色带抑制」与「小特征保护」上形成差异优势。

### 0.2 五维结论概览（当前状态 vs 目标）

| 维度 | 现状评级 | 主要拖后腿的缺陷 | 优化后目标 |
|---|---|---|---|
| 边缘清晰度 | ★★★☆☆ | P0-2 硬 2 类切割、P1-5 连通域合并吞细描边 | ★★★★★ |
| 色块纯净度 | ★★★★☆ | P1-6 限色贪心删对比色、P1-7 outline 覆盖保护特征 | ★★★★★ |
| 特征完整度 | ★★★☆☆ | P0-3 小特征下限过高、P1-5 合并吞小点缀 | ★★★★★ |
| 色号还原度 | ★★★★☆ | P1-4 ciede76 预筛漏色、P2-9 彩度硬阈跳变 | ★★★★★ |
| 细碎杂色数量 | ★★★☆☆ | P2-10 dot 簇阈值高、缺末段区域一致性收口 | ★★★★★ |

### 0.3 方法与边界（透明声明）

1. **本环境限制**：沙箱拦截 esbuild 服务子进程（有名管道 EPERM），`vitest` / `vite build` 无法在沙箱内启动；tsp 类单进程工具（`tsc`）可用但不足以构建可执行管线。故**未运行 GUI 截图级对比**，而是对现有源码逐行走查 + 用可复现合成测试样本推导输出。
2. **测试样本**：因无法从外网稳定拉图（pwsh 网络被沙箱拦截、raw 源偶发失败），改用**按目标场景精确定义的合成测试图**（含渐变、小面积高反差、柔边、浅色系四类），其像素结构可完全复现，覆盖等价难点。若需真实照片，用 §3 的接线方式替换即可。
3. **对标项目**：以 `docs/00`（已实读源码/许可，经严格核验）为主体事实，辅以本轮对 [pixel-mosaic](https://github.com/yogthos/pixel-mosaic)、[pyssla-designer](https://github.com/heisendelta/pyssla-designer) 的公开资料检索。凡属「读源码」所得结论均标注可信度高；仅据 README/仓库结构推断的标注「待核」。

## 1. 开源对标调研

### 1.1 调研方法

- 检索面：`web_search`（GitHub 像素画转换、拼豆图纸生成、像素化算法）+ 对候选仓库抓取 README/源码结构/许可证。
- 评优标准：算法工程化完整度、采样/量化方法是否感知颜色模型、是否保留边缘/小特征、是否做色块合并与限色、可视交互成熟度、许可证可引用性。
- 许可证红线：沿用 `docs/00` 结论——**AGPL/GPL/无证/来源存疑的仓库只参考思路、不照抄代码与数据**。

### 1.3 综合提炼：商用级算法应具备的 6 个要点

1. **感知色空间匹配**：CIEDE2000（或 Oklab ΔE）＞ RGB 欧氏（pyssla 弱、Pindo 强）。
2. **采样阶段感知结构**：平坦区用均值（保渐变）、结构区用特征/主导色（保边缘），由**边缘/方差**引导切换（pixel-mosaic 思路）。
3. **小特征保护要前置**：在降采样**之前**检测并在**之后**强制写回，且下限要足够低（眼科、细线、单点）。
4. **色块合并要代价化**：不能无脑并「最邻近邻近色」，需考虑**接触长度/周长比**，避免吞细描边（Pindo edge-aware 精神）。
5. **限色要保对比角色**：极端色、主色、边缘/描边色成为「必保角色」，其余按冗余度淘汰。
6. **确定性 + 可 A/B**：全部阶段纯函数、禁随机、可注入参数对比（pyssla 可插拔降采样的启示）。

- **T1**：主打「柔和渐变 + 柔边」。直击 P0-1（亮度轴空桶平滑失效）与 P0-2（硬 2 类切割 → 带纹）。

- **T3**：主打「小特征完整度」。直击 P0-3（小特征下限过高）、P2-10（dot 簇阈值）。
- **T4**：主打「色号还原 + 杂色控制」。直击 P1-4（ciede76 预筛漏色在低彩度密集区最伤）、P2-11（主导色桶均值误差）。

## 3. 自测与效果对标（逐行走查模拟）

> 口径：以下推导基于对 `src/core` 现行源码的逐行走查，结合出厂默认参数（`docs/29` 与 `src/app/options.ts`）。五维评级为 **★（差）~ ★★★★★（优）**，相对量表，用于横向比较 PixelBean 现 v1.2 与对标项目方法。

### 3.1 出厂默认路径（先固化，推导才能准确）

由 `src/app/options.ts` + `src/worker/convert.worker.ts` + `src/core/pipeline/index.ts` 可得：

- **照片（默认）**：`features(主导色V2+特征保护)` → `matchGridDetailed` → `mergeAdjacent`。**不跑**后处理（`post=undefined`）。
- **卡通**：`features(主导色V2+特征保护)` → `matchGridDetailed` → post（`speckleCleanV2`→`shadowSimplifyV2(lvl1)`→`clusterLimitV2(K=24)`→`outline`）。**不跑** merge。
- **线稿**：`dominant`（无特征保护）→ `matchGridDetailed` → post（speckle→clusterLimit(K=16)），无 shadow/outline。
- **像素表情**：`dominant`（无特征保护）→ `matchGridDetailed`，无 post、无 merge。

### 3.2 五维对比表（按样本）

#### T1 3D 卡通柔边渐变

| 维度 | 当前 PixelBean | 依据/机理 | 对标方法预期 |

## 4. 问题分级清单（P0/P1/P2 → 算法环节）

> 分级标准：**P0** = 出厂默认路径（照片/卡通）上的明确正确性 bug 或核心价值落差；**P1** = 特定场景质量显著下降或正确性风险；**P2** = 次要/边界。均标注**文件:行**与**所属环节**。

| 级别 | 编号 | 问题 | 环节 | 文件/行 | 影响 |
|---|---|---|---|---|---|
| **P0** | P0-1 | **E1 主导色「空桶平滑」亮度轴完全失效** | 采样（降采样） | `downsample.ts:206` `LAB_NEIGHBOR_WEIGHT=[1,0.5,0.5]`；`271–289` 权重公式 `dl===0?w[0]:1-w[0]`，因 w[0]=1 → 所有 L 方向邻居权重=0 | 柔和渐变（T1）出现亮度阶跃/带纹，直接违反对奶龙类对象的核心要求 |
| **P0** | P0-2 | **主导色方法把柔和渐变硬切 2 类 → 明显色带** | 采样/特征保护 | `features.ts:108–178` `classifyRegion`（阈值两分）；`171–176` soft/boundary 输出 `meanF` 或 `meanM` 二选一 | 柔边/渐变被拉成硬阶，边缘清晰度与渐变性双损 |
| **P0** | P0-3 | **小特征保护下限过高，微小但有意义特征被吞** | 特征保护 | `features.ts:9` `FEATURE_REGION_MIN_PX=8`；`11` `FEATURE_SHARE_MIN=0.02`；`16` `FEATURE_DOT_MIN_TOTAL=4`；`237` `cap=max(24,2%*cells)` | 眼/嘴/孤立点被主色吞掉，特征完整度最短板（T3） |
| **P1** | P1-4 | **色匹配用 ciede76 预筛 top-8 可能漏掉感知最优色** | 匹配 | `match.ts:23–45` `nearestPaletteCandidates` | 低彩度密集区色号还原下降（T4） |
| **P1** | P1-5 | **连通域合并吞掉细描边/小面积高对比点缀** | 后处理（合并） | `merge.ts` `MERGE_DE=6`、`MERGE_MIN_AREA=3`、`MERGE_MAX_AREA=40`；`114–116` 按最近邻并入 | 边缘清晰度下降（T2）；特征完整度下降（T3） |
| **P1** | P1-6 | **clusterLimitV2 贪心删除可能牺牲边缘/描边对比色** | 后处理（限色） | `clusterLimitV2.ts:112–145` `trimToK` 删与剩余色最近者 | 限色后对比色丢失，边缘弱化（T2） |
| **P1** | P1-7 | **outline 不尊重 protect 掩码** | 后处理（描边） | `outline.ts:52–96` 不检查 `protect` | 被保护的小特征若在亮度边界会被描边覆盖 |
| **P1** | P1-8 | **limitColors（非后处理路径）忽略 protect + 保护集选取粗糙** | 匹配后（限色） | `pipeline/colorLimit.ts` `protectColors` 4%/4%/3%，`nearestInSet`；无 protect 参数 | 自定义模式关闭部分后处理时，限色可能误伤保护特征 |
| **P2** | P2-9 | **LOW_CHROMA=25 硬阈值导致匹配行为在 C=25 处不连续** | 匹配 | `match.ts:104–106` | 色号在彩度中段可能跳变 |
| **P2** | P2-10 | **dot 特征需同色点 ≥4 且 ΔE≤12 成簇才写回** | 特征保护 | `features.ts:16` `FEATURE_DOT_MIN_TOTAL=4`；`290–301` 聚类 | 2–3 点构成的小特征不保留 |
| **P2** | P2-11 | **主导色只取桶均值，无感知混合；桶粗（L10×a12×b12）** | 采样 | `downsample.ts:202–212` 桶定义；`298–303` 取桶均值 | 多源色格落到稀疏色区，产生「非整非均匀」色 |

> 已确认的根因优先级：**P0-1（绝对 bug）> P0-2（结构性）> P0-3（阈值）**；三者共同导致「奶龙类柔边渐变 + 小特征」场景的商用落差。P1 组为「特定场景质量下降 + 正确性风险」，P2 组为「边界/次要」。

## 5. 商用级算法优化方案（兼容现有管线）

> 设计原则：
> 1. **不破坏数据契约**：所有阶段仍以 `CellImage`(RGBA) 输入、`Pattern`(`cells:Int16Array + codes + options`) 输出；辅助信息（protect 掩码）继续以 `Uint8Array` 并行透传；不改 `ConvertOptions` 必需字段。
> 2. **挂接点明确**：新增逻辑以**独立纯函数**放入既有文件或新增子模块，`pipeline/index.ts` 仅在不改变对外签名前提下**按序**调用，保证 `protocol`/Worker/前端调用不变。
> 3. **确定性**：全程无随机；参数以 const 常量集中导出，便于 A/B 与回归用例固定。
> 4. **复杂度**：满足 120×120 ≤ 2s（现有预算）。

### 5.1 方案一：采样重构（多模态感知主导色采样）——修复 P0-1、P0-2、P2-11

**目标**：平坦区保渐变（均值色）、结构区保纯度（主导色），并修复亮度轴空桶平滑 bug。

**5.1.1 修复空桶平滑 bug（P0-1）**

替换 `downsample.ts:206` 的 `LAB_NEIGHBOR_WEIGHT`，并重写权重公式为对称衰减：

```text
// 修正：对称 3D 邻域衰减，避免"L 轴邻居权重恒为 0"
LAB_NEIGHBOR_WEIGHT = [0.5, 0.5, 0.5]          // 每轴距离 1 的衰减
EMPTY_SMOOTH = 0.5

score(key) = counts[key]
           + EMPTY_SMOOTH * Σ_{dl,da,db∈{-1,0,1} \ (0,0,0)}
                 neighbor_count(l, a, b)
                 * [dl==0 ? 1 : LAB_NEIGHBOR_WEIGHT[0]]
                 * [da==0 ? 1 : LAB_NEIGHBOR_WEIGHT[1]]
                 * [db==0 ? 1 : LAB_NEIGHBOR_WEIGHT[2]]
```
> 说明：原式 `x===0 ? w : 1-w` 是错的（不依赖轴编码），`[1,0.5,0.5]` 使亮度轴 `1-1=0`。改为 `x===0 ? 1 : w`，即「中心轴满权、偏移轴衰减」，三轴对称，亮度方向不再失效。

**5.1.2 方差引导的多模态采样（P0-2、P2-11）**

每个格子**同时**计算均值色（`downsampleAverage` 的线性-RGB 面积均值）与 Lab 主导色（V2），再按**格内色散度**插值融合：

```text
for each downscaled cell:
    meanRGB = linearAreaMean(subregion)         // 已有，保渐变
    domRGB  = labDominantV2(subregion, fixedBugs) // 已有，保纯度
    spread  = std( perPixel Lab ) / 128.0       // 格内 Lab 色散（感知方差）
    // 平坦（spread 小）→ 主导色更纯；渐变/混合（spread 大）→ 均值更忠实
    t = smoothstep(VAR_LOW, VAR_HIGH, spread)   // VAR_LOW=0.04, VAR_HIGH=0.18
    outRGB = lerp(domRGB, meanRGB, t)
```
> 阈值建议：`VAR_LOW=0.04`，`VAR_HIGH=0.18`。作用：**平坦区**（T2 平涂）保持纯净；**渐变区**（T1 奶龙）连续过渡、抑制带纹。该插值在 `downsampleDominantV3` 内完成，签名与 `downsample()` 兼容（返回 `Uint8ClampedArray`）。

**5.1.3 桶粒度微调（P2-11）**

`L:10→12`、`a:12→14`、`b:12→14`，使浅色/近白区（T4）不因桶粗跳格。成本可接受。

### 5.2 方案二：小特征保护增强（前置 + 降阈值）——修复 P0-3、P2-10

**目标**：让「微小但有意义」的特征（眼/嘴/孤立点）在主导色塌缩前被识别并强制写回。

**5.2.1 前置检测（在降采样之前，源码级）**

新增 `preDetectFeatures(source)`：对**源图**（非降采样格子）做粗粒度特征检测，产出与**输出网格对齐**的 `protect` 掩码。检测用「局部极值 + 对比度」：

```text
preDetectFeatures(source, outW, outH):
    for each output cell (gx,gy):
        sub = source cell subregion
        Lmin, Lmax = min/max perLinearLuma(sub)
        contrast = Lmax - Lmin
        if contrast >= PRE_CONTRAST (0.25):
            // 存在高反差子结构 → 保护该格
            protect[gy*outW+gx] = 1
            // 记录小侧（离群簇）均值，供写回
            store featureMean[cell] = meanOfMinOrMaxCluster(sub)
```
> 说明：这是**源码级**保护，先于 `downsampleDominant`，避免「采样已塌缩、后续检测无从找回」。

**5.2.2 降阈值（后置写回）**

- `FEATURE_SHARE_MIN: 0.02 → 0.008`（占格 <2% 的极小块也可触发）。
- `FEATURE_DOT_MIN_TOTAL: 4 → 2`，且当 `deltaY ≥ 0.30` 时**单点也写回**（强对比单点必保）。
- `cap: max(24, 2%*cells) → max(24, 5%*cells)`（提高保护预算）。
- 保持 `protect` 对后续 `merge/speckle/shadow/clusterLimit` 的「跳过」语义（已有），并新增对 `outline` 的跳过（见方案四）。

**5.2.3 写回保证**：`downsampleWithFeatures` 中，凡 `protect[cell]=1` 的格，其 `cells` 颜色**强制替换**为特征均值（`writeFeature`），不再被主导色覆盖。

### 5.3 方案三：连通域色块合并（代价化）——修复 P1-5

**目标**：只合并「真冗余」同色块，**不吞**细描边/小面积高对比点缀。

**5.3.1 合并代价模型**

```text
mergeAdjacentV2(pattern, palette, protect, deThr=6, minArea=3, maxArea=40):
    for each same-color component (size in [minArea, maxArea], not protected):
        contact = Σ 与某邻色 X 的相邻边数
        perim   = component 周长（含边界+内部空格边缘）
        ratio   = contact / perim                 // 贴附强度
        target  = 接触边数最多的邻色 X
        delta   = ciede2000(component.color, target)
        areaRatio = targetArea / componentArea     // 目标主块相对大小
        // 仅当"真冗余"才并入：
        //   a) 色差极小；b) 贴附强（几乎被包裹）；c) 目标明显更大
        if delta <= deThr AND ratio >= TIGHT_RATIO(0.6)
           AND areaRatio >= BIG_RATIO(3.0):
            merge(component, target)
```
> 关键变化：新增 `TIGHT_RATIO=0.6`（贴附强度下限）与 `BIG_RATIO=3.0`（主块相对大小）。细描边（接触长度小、perim 大、ratio 低）与「同色系但独立的小块」不再被并入 → 边缘/特征保留。

### 5.4 方案四：边缘收敛增强（降低 halo + 保护描边）

**目标**：让抗锯齿/柔边在匹配后收敛到区块内，消除「半色 halo」，并让描边/特征不被抹平。

**5.4.1 边界格收敛**（新增 `edgeConverge`，纯函数，位于 `post/`）

```text
edgeConverge(pattern, palette, protect):
    for each cell on a boundary (≥2 个邻格不同色):
        if protect[cell] == 1: continue          // 保护特征不动
        // 用 4 邻格做"去杂"多数裁决：若该格颜色只在 1 个方向出现，改投邻格主导色
        neig = 4 邻格颜色（去重）
        if neig.size == 2 and 该格不属于两个簇的任一"主"色:
            将该格重指派为两个邻簇中 Lab 最近者
            // 且仅在 ΔE(该格,邻色) > EPS 时执行，避免过度改色
```
> 作用：把抗锯齿产生的「介于两色之间」的格子收敛到区块主色 → 边缘更硬、无灰边；同时因跳过 `protect`，小特征（眼）不被抹平。

**5.4.2 outline 尊重 protect（修复 P1-7）**

`outline.ts` 中 `marked[i] = protect[i]===1 ? 0 : (lumaBoundary ? 1 : 0)`；即被保护格不描边。

### 5.5 方案五：色板匹配优化（去预筛 + 连续权重）——修复 P1-4、P2-9

**目标**：色号还原在低彩度密集区更准，且匹配行为连续。

**5.5.1 去掉 ciede76 top-8 预筛（或保守放大）**

```text
nearestPaletteIndex(lab, palette):
    // 方案 A（最稳，推荐）：全程 ciede2000 扫描全部固体色
    best = argmin_{i} ciede2000(lab, palette.labs[i])
    // 提前退出：利用 ciede76 下界剪枝
    //   lb(i) = sqrt( (dL/SL)^2 + (dC/SC)^2 + (dH/SH)^2 ) >= |dL|/SL + sqrt(((dC/SC)^2+(dH/SH)^2) )
    //   当 lb(i) > bestUpperBound 可跳过该 i（保守、绝不漏最优）
```
> 性能：匹配为 O(N·P)，P 为单品牌颜色数（约 90–291）。120×120=14400 格 × 291 色 ≈ 419 万次 ciede2000，可接受；若更大色板，用可选的 Lab kd-tree（保持确定性，距离函数用有序遍历）代替。

**5.5.2 连续权重取代硬阈值（P2-9）**

```text
// 以彩度 C=(a^2+b^2)^0.5 归一化权重，替代 LOW_CHROMA=25 的二值开关
ramp = clamp(1 - C/45, 0, 1)          // C 越小（越浅/越灰）权重越强
kL = 1 - 0.2*ramp                      // 浅色增强亮度约束（实际用 kL<1 放大亮度差权重）
kC = 1 + 0.5*ramp                      // 彩度约束
kH = 1 + 0.5*ramp                      // 色相约束
```
> 适用：匹配阶段 `chroma < LOW_CHROMA ? weighted : plain` 改为**全程 `ciede2000Weighted(lab, lab2, {kL,kC,kH})`**，C=25 处不再跳变。

### 5.6 方案六：末段区域一致性收口（降细碎杂色）——补 P2-10/P2-11

**目标**：在限色后、描边前做一次**单遍、确定、跳过保护**的区域一致性修正，显著降低细碎杂色数量，不新增色号。

```text
finalRegionClean(pattern, palette, protect, deThr=8, minSame=3):
    for each cell:
        if protect[cell]==1: continue
        cnt = 4 邻格颜色计数（排除自身与空格）
        best = 出现最多的邻色
        if cnt[best] >= minSame AND ciede2000(self, best) <= deThr:
            cell = best             // 并入多数，单遍不迭代
```
> 说明：即为现有 `regionClean`（`post/regionClean.ts`），当前未接入任何预设。建议**默认对卡通/照片开启**（作为 `runPostPipeline` 的末段，位于 `clusterLimitV2` 之后、`outline` 之前），并在照片路径（当前无 post）作为独立的可选收口暴露。

## 7. 风险与开放问题

1. **匹配去预筛的代价**：低彩度密集中 ciede2000 全扫描在 ≥300 色 + 150k 格时需评估是否引入 kd-tree / 分桶预剪枝（保持确定性）。
2. **方差融合的阈值**：`VAR_LOW/VAR_HIGH` 与桶粒度调整需用回归集校准，避免「渐变保留」与「纯净度」此消彼长。
3. **前置检测的误保护**：把「高反差的纹理」误当特征会抬升特征预算与色号数 → 需限制 `protect` 比例上限（建议 ≤ 6%）。
4. **合成样本 vs 真实照片**：本方案第 2、3 节用合成样本。真实照片接入只需把合成 RGBA 换成 `CellImage`（`data` + `width/height`），即可直接喂 `convertPipeline`；建议后续用 docs/30/32 的 40→34 色、−23% 孤立小块等真实案例做最终验收。
