## 4. 质量回归（核心结论）

### 4.1 兔子图 A/B（45×58，图片模式，其余全默认）

| 指标 | 去背景开（本版默认） | 去背景关（= 上一版） | 判读 |
|---|---:|---:|---|
| 有效格 | **565** | 2610 | 移除 78% 原有内容 |
| 使用色数 | 29 | 43 | — |
| 连通域数 | **7** | 1 | 主体被打碎 |
| 最大连通域占有效格 | **66%** | 100% | 主体不连通 |
| 灰中调格占比 | **58.2%** | 30.4% | 更灰、更脏 |
| 预览透明像素 | 521060 | 0 | 背景被清空（唯一达成的目标） |

**逐格关系**：`ON ∩ OFF = 565`、`仅 ON = 0`、`仅 OFF = 2045` —— 开启态是关闭态的**真子集**，即新逻辑只做了删除，没有新增任何主体内容。

### 4.2 掩码目检（`after-mask.png`）

掩码图上（白=主体）：**头部、颈、躯干整体判为背景（黑）**，只保住双眼、额点、双耳尖、腹部米色带与腿部灰影。也就是说，本应被去掉的**灰色接触阴影被当成了主体**，本应保留的**白色身体被当成了背景**——与 `docs/37` 的意图正好相反。

### 4.3 根因：这不是调参问题，是结构性失效

`diag-subject.mjs` 实测（ΔE76 相对边界背景色中位数）：

| 采样点 | ΔE | | 采样点 | ΔE |
|---|---:|---|---|---:|
| 背景四角 | **11.53** | | 头顶 | **3.87** |
| 颈 | 4.96 | | 脚下阴影 | 4.10 |
| 头部中心 | 13.45 | | 腹部 | 12.54 |

**主体比背景更接近「背景色」**。洪水从四边种子出发，第一判据 `ΔE(px, bg) ≤ tol(13)` 对白身白底一律成立；第二判据（梯度 ≤ 18）在柔光 3D 渲染的软过渡上**从不触发**——`edge` 从 2 调到 18，头部覆盖率只从 0.185 变到 0.176，形同虚设。

阈值网格扫描（`tol × edge`，头部/腹部应≈1、背景应≈0）：

| tol | 结果 |
|---:|---|
| 3 / 6 / 9 | 洪水连背景都进不去 → 去背景**几乎不生效**（头部 1.0、背景 0.99） |
| **13（默认）** | 洪水连主体一起吞 → 头部 0.176、腹部 0.292、背景 0 |
| 20 | 更激进 → 头部 0.13 |

**不存在能同时保住头部的 `(tol, edge)` 组合**。`docs/37` §7 自陈的「主体与背景完全同色且无轮廓梯度时洪水可能渗漏」在**目标样例上 100% 发生**。

### 4.4 内置样例与首屏

| 样例 | ON 有效格 | OFF 有效格 | 现象 |
|---|---:|---:|---|
| `sample-photo.jpg`（首屏默认图，模糊彩底人像） | 1917 | 2668 | 只抠掉外圈 28%，四周留下锯齿状透明边框，背景残余仍留在画内（`first-visit-desktop.png`） |
| `sample-photo.jpg` + 卡通预设 | 1917 | 2668 | 同上 |
| `sample-cartoon.png` | 2494 | 2494 | 无透明边，回退全主体，未受影响 |

首屏（无草稿的新用户）看到的就是上面那张「透明锯齿边框 + 背景残块」的图，而不是完整人像。

### 4.5 其他边界

- **纯色图 → 空图纸**：纯红 60×60 图，开启后有效格 **0**（关闭态 400）。`extractSubject` 把整图判为背景，管线产出空 pattern。
- 硬边主体（白底 + 灰边方块）正常：mask 0.694，主体完整、白边清除 —— 现有单测覆盖的正是这一类，因此全绿。

## 5. 优化前后对比结论

1. **关闭开关 = 严格等于上一版**：`compare-off.mjs` 用 `HEAD` worktree 独立跑，逐格差异 **0**，hash 一致（`1357321575`，2610 格）。所以「关掉即回退」成立，A/B 对照有效。
2. **开启开关 = 劣化**：本次任务指定的核心样例上，主体从「完整可辨识」变为「打碎成 7 个色块、头部消失、灰影反被保留」。
3. 本次改动**确实**消除了白底与灰影在输出中的占比（背景格清空），但代价是把主体一起清掉了——属于「解决了症状、毁掉了主体」。

## 7. 结论与建议

**验收结论：不通过。** 功能链路、默认配置、透明预览、导出、多端与构建全部达标；但验收清单第 3 组「质量回归」四条中三条不满足，且发生在 `docs/37` 自己指定的目标样例上。`docs/38` 的「全部通过」与 README 中「✅ 已实现并自测（178 例全绿）」不能作为质量达标依据。

**建议处置（按优先级）**：

1. **立即（止血）**：把 `removeBackground` 默认值改回 `false`（照片/卡通预设同样置 false），保留开关供用户主动启用。这使默认观感严格回到上一版，满足「至少不劣化」，且关闭路径已验证逐格等同旧版。
2. **再修算法（若要默认开启）**：当前纯颜色洪水对本类「白底 + 软阴影 + 近白主体」图结构性失效。可选方向：
   - 增加**可信度兜底**：若 `subjectMask` 占比低于阈值（如 25%）或主体最大连通域占比过低，判定抠图不可信 → 回退全主体（可同时修掉 P2-2 的空图纸）；
   - 引入**主体侧线索**（梯度/阴影方向/最大连通域），或改用 alpha matting 类算法；
   - 无论哪种，必须先用 `rabbit-source.png` 做回归门禁：断言头部矩形区 mask 覆盖率 > 0.8、主体连通域占比 > 0.9。
3. **补测试**：把兔子图（或其降采样版）纳入单测/回归夹具，替换当前只用硬边合成图的覆盖方式。
4. **同步文档**：`docs/38` 结论与 README 状态需按本报告更正。

**复现命令**：`npm run dev` 后执行 `node .tools/acceptance/run.mjs`、`node .tools/acceptance/probe.mjs`、`node .tools/acceptance/diag-subject.mjs`。
